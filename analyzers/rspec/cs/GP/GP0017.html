A property, field or positional record member representing a date without a time component should not have Utc in its name.

Why is this an issue?

The Utc suffix is a promise about a time zone - it tells the reader "this value carries a specific point in time, expressed in Coordinated Universal Time". A date-only value (DateOnly, or the shared GP.Juno.Dates.LocalDate) has no time-of-day and therefore no time zone to speak of. Naming it ExpirationDateUtc raises a question the type can't answer: was this truncated from a UTC instant, and if so, at which moment of that day? Dropping the suffix removes the false promise and matches the convention that a name only carries Utc when the value genuinely is a UTC point in time.

The same applies to NodaTime.LocalDate and to positional record parameters, which declare public members under their parameter names.

Members marked [Obsolete] are excluded. A compatibility alias may need to preserve its published name while directing consumers to the correctly named replacement.

public DateOnly ExpirationDateUtc { get; set; }

How to fix it

Rename the member to drop the Utc suffix.

Code examples

Noncompliant code example

public class JobOffer
{
    public DateOnly ExpirationDateUtc { get; set; } // Noncompliant {{Rename 'ExpirationDateUtc' - a date without a time component should not have 'Utc' in its name.}}
}

Compliant solution

public class JobOffer
{
    public DateOnly ExpirationDate { get; set; }
}
