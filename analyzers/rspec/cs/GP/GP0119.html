A migration should create tables and indexes with FluentMigrator expressions, not with CREATE TABLE or CREATE INDEX inside Execute.Sql.

Why is this an issue?

Creating complete tables or indexes through Execute.Sql bypasses FluentMigrator's schema expressions. The migration becomes harder to review and refactor, loses FluentMigrator's structured representation, and encourages the corresponding Down operation to drift away from the schema created in Up.

This rule recognizes the FluentMigrator API semantically and reports only when the first instruction of constant SQL is CREATE TABLE or CREATE INDEX. Raw SQL remains allowed for operations without an adequate FluentMigrator expression, such as adding a CHECK constraint with ALTER TABLE, creating a schema, defining or executing a stored procedure, using temporary tables, or migrating data.

How to fix it

Use Create.Table(...) and Create.Index(...) expressions. Keep Execute.Sql only for database operations that FluentMigrator cannot represent directly.

Code examples

Noncompliant code example

Execute.Sql("""
    CREATE TABLE [dbo].[BookItems]
    (
        [Id] uniqueidentifier NOT NULL,
        [Isbn] nvarchar(20) NOT NULL
    );

    CREATE INDEX [IX_BookItems_Isbn] ON [dbo].[BookItems] ([Isbn]);
    """); // Noncompliant

Compliant solution

Create.Table("BookItems").InSchema("dbo")
    .WithColumn("Id").AsGuid().NotNullable().PrimaryKey()
    .WithColumn("Isbn").AsString(20).NotNullable();

Create.Index("IX_BookItems_Isbn")
    .OnTable("BookItems").InSchema("dbo")
    .OnColumn("Isbn").Ascending();

// FluentMigrator has no expression for this CHECK constraint.
Execute.Sql("""
    ALTER TABLE [dbo].[BookEditions]
    ADD CONSTRAINT [CK_BookEditions_AuthorsJson]
        CHECK (ISJSON([AuthorsJson]) = 1);
    """);
