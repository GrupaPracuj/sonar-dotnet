A published event should say which business object or process it is about.

Why is this an issue?

An event that carries data but no identifier tells a consumer that something happened without saying to what. That makes it unusable for the things consumers actually do with events: update their own copy of a record, correlate the fact with work already in progress, or decide whether a newer event has superseded an older one. All of those need a stable key, and none of them can use one that only exists inside the producer.

MessageId does not count, and neither does CorrelationId. They identify the message, not the thing the message is about: a redelivery produces a different MessageId for the same fact, and republishing through an outbox produces another one again. A consumer keyed on them cannot recognise that it has already seen this event, which is precisely the case idempotency depends on.

public sealed record PaymentReceived(decimal Amount, string Currency, DateTimeOffset OccurredAt);

appConfig.Publishes<PaymentReceived>();

A member counts as a business identifier when its name ends with Id, Number, Reference, Code or Key - configurable through identifierSuffixes - and is not one of the transport metadata names.

Exceptions

An event with no data members at all is not reported. A marker event such as MaintenanceModeEnabled is about the system rather than about a particular object, so there is no identifier for it to carry - and requiring one would only produce a field nobody fills in.

How to fix it

Add the identifier of the thing the event is about, named after that thing. Where the event is about a process rather than an entity, the process identifier is the right key.

Code examples

Noncompliant code example

public sealed record PaymentReceived(decimal Amount, string Currency, DateTimeOffset OccurredAt);

appConfig.Publishes<PaymentReceived>(); // Noncompliant {{'PaymentReceived' carries no business identifier, so a consumer cannot tell what it is about.}}

Compliant solution

public sealed record PaymentReceived(Guid PaymentId, decimal Amount, string Currency, DateTimeOffset OccurredAt);

appConfig.Publishes<PaymentReceived>();
