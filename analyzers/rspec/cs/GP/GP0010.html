A GET endpoint should respond with 200 OK and an empty collection instead of 404 Not Found when the collection it returns has no items.

Why is this an issue?

404 Not Found means the requested resource or route doesn't exist. A collection query that runs successfully but matches zero rows is a different situation: the route and the resource (the collection) both exist, there just happen to be no items in it right now. Returning 404 in that case conflates "this endpoint doesn't exist" with "this list is empty" and misleads clients into treating a normal, valid response as an error.

The rule covers MVC controller actions and inline Minimal API MapGet handlers. It reports only when the 404 branch is explicitly guarded by an emptiness check such as orders.Count == 0, orders.Length == 0, or !orders.Any(), or is the opposite branch of the corresponding non-empty check. The checked collection must be the same symbol that the endpoint returns through Ok(...).

This deliberately excludes unconditional 404 responses and conditions concerning identifiers, query failures, or missing logical parent resources. A collection-shaped return type alone does not prove that the 404 means an empty collection.

[HttpGet]
public IActionResult GetUsers(int customerId)
{
    var users = FindUsers(customerId);
    if (!users.Any())
    {
        return NotFound();
    }

    return Ok(users);
}

Exceptions

The response factory is resolved semantically: NotFound()/StatusCode(404) must come from Microsoft.AspNetCore.Mvc.ControllerBase/Controller, or from the Minimal API Results/TypedResults. A same-named helper declared elsewhere - including on the controller itself - is not reported.

How to fix it

Return Ok(...) with an empty collection instead of NotFound() when the collection query is valid but matches nothing.

Code examples

Noncompliant code example

[HttpGet]
public IActionResult GetUsers(int customerId)
{
    var users = FindUsers(customerId);
    if (!users.Any())
    {
        return NotFound(); // Noncompliant {{GET endpoints returning collections should return 200 with an empty collection instead of 404.}}
    }

    return Ok(users);
}

Compliant solution

[HttpGet]
public IActionResult GetUsers(int customerId)
{
    var users = FindUsers(customerId);
    return Ok(users);
}
