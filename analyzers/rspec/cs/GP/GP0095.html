A CORS policy should not allow the literal null origin.

Why is this an issue?

Browsers send Origin: null for requests from contexts such as sandboxed iframes and local files. Trusting that value allows unrelated untrusted documents to satisfy the same policy and access a response intended for a trusted caller.

How to fix it

Remove null and list only explicit trusted origins. Do not emit Access-Control-Allow-Origin: null manually.

Code examples

Noncompliant code example

policy.WithOrigins("null"); // Noncompliant {{Remove the 'null' origin from this CORS policy and allow only explicit trusted origins.}}

Compliant solution

policy.WithOrigins("https://trusted.example");

Exceptions

Only compile-time constant values equal to the lowercase CORS origin null are reported. Dynamic configuration and unrelated APIs are not inferred.
