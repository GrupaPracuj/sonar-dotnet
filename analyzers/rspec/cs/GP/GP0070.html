Under the GP contract-modeling policy, an enum put on the wire should not be a flags enum.

Why is this an issue?

A flags enum travels as one combined number, and the receiving side has to decompose it against the members it knows. That is fine while both sides know the same members, and becomes ambiguous when the producer adds a flag: an older consumer can retain the numeric bits, but it cannot name or interpret the new portion without an explicit mask and policy. Whether a textual representation is accepted, rejected, or preserved also depends on serializer options. The unknown bits are not necessarily discarded; the interoperability problem is that their meaning is unavailable to the older model.

Flags also make the contract's meaning implicit. Permissions = 6 documents nothing on its own, so reading a message off the broker or out of the error queue requires the enum definition at the exact version the producer used. And combinations that are invalid in the domain are still representable, so the contract admits values the producer would never send and the consumer has to defend against.

[Flags]
public enum NotificationChannels
{
    None = 0,
    Email = 1,
    Sms = 2,
    Push = 4,     // an older consumer can preserve the bit but cannot interpret its meaning
}

This is a convention rather than a framework rule - Microsoft's guidance covers how to design a flags enum correctly, not whether to put one in a contract. The objection here is specific to a service boundary, where the two sides are versioned independently.

Exceptions

Only enums a contract actually exposes are reported. A flags enum used inside the service is unaffected, which is where most of them belong.

How to fix it

Follow the GP policy and send the set explicitly as a read-only collection of a plain enum. Each selected value then has a separate representation, which makes validation, compatibility handling, and domain constraints explicit instead of hiding them in a combined bit mask.

Code examples

Noncompliant code example

[Flags]
public enum NotificationChannels // Noncompliant {{'NotificationChannels' is a flags enum exposed by a contract; model the selected values explicitly.}}
{
    None = 0,
    Email = 1,
    Sms = 2,
}

public sealed record NotificationRequestedContract(Guid UserId, NotificationChannels Channels);

Compliant solution

public enum NotificationChannel
{
    Unknown = 0,
    Email = 1,
    Sms = 2,
}

public sealed record NotificationRequestedContract(Guid UserId, IReadOnlyList<NotificationChannel> Channels);
