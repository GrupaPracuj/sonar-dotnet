Database access should be performed through Juno IDbExecute. Connections should not be created with new SqlConnection(...) or directly through a DbProviderFactory, and Dapper calls should remain inside an IDbExecute operation.

Why is this an issue?

Constructing the connection yourself means supplying the connection string yourself, which is the actual problem: the address, credentials, failover target and pooling settings stop coming from the service's configured data source and start coming from whatever string is in scope at that point. It also bypasses the transaction accessor, so the new connection is invisible to any Juno transaction that is already open - work you believe is transactional silently is not.

public async Task<Order> Find(int id)
{
    using var connection = new SqlConnection(_connectionString);
    return await connection.QuerySingleAsync<Order>("select * from Orders where Id = @id", new { id });
}

Dapper is reported outside IDbExecute. Keeping SQL in an operation object prevents controllers and application services from becoming ad-hoc persistence layers while still allowing Juno to supply the ambient connection and transaction.

The rule targets Dapper Query* and Execute* operations. Configuration and utility APIs such as SqlMapper.AddTypeHandler, AddTypeMap, PurgeQueryCache and AsTableValuedParameter do not access a database and are not reported.

Inside an IDbExecute, Dapper operations must receive the IDbTransaction parameter supplied by Juno. Omitting it can make one command escape the surrounding transaction or fail at runtime when the provider requires commands on a transactional connection to enlist explicitly. The same requirement applies when the operation uses a Dapper CommandDefinition.

How to fix it

Take the connection from IAdoConnectionFactory.CreateConnection(), or express the work as an IDbExecute and let Juno pass in the connection and the ambient transaction.

Code examples

Noncompliant code example

public async Task<Order> Find(int id)
{
    using var connection = new SqlConnection(_connectionString); // Noncompliant {{Perform database access through Juno IDbExecute instead of using 'SqlConnection' directly.}}
    return await connection.QuerySingleAsync<Order>("select * from Orders where Id = @id", new { id });
}

public Task<Order> Execute(IDbConnection dbConnection, IDbTransaction dbTransaction = null) =>
    dbConnection.QuerySingleAsync<Order>("select * from Orders where Id = @id", new { id = _id }); // Noncompliant {{Pass the IDbExecute transaction to this Dapper operation.}}

Compliant solution

public class FindOrder : IDbExecute<Order>
{
    private readonly int _id;

    public FindOrder(int id) =>
        _id = id;

    public Task<Order> Execute(IDbConnection dbConnection, IDbTransaction dbTransaction = null) =>
        dbConnection.QuerySingleAsync<Order>("select * from Orders where Id = @id", new { id = _id }, dbTransaction);
}
