A database connection should be created by Juno: either supplied to an IDbExecute, or obtained from IAdoConnectionFactory.CreateConnection(). The two are equivalent as far as this rule is concerned.

Why is this an issue?

Constructing the connection yourself means supplying the connection string yourself, and that is the actual problem: the address, credentials, failover target and pooling settings stop coming from the service's configured data source and start coming from whatever string happened to be in scope at that point. Such a connection is also invisible to a Juno transaction that is already open, so work you believe is transactional is not.

using var connection = new SqlConnection(_connectionString);

Only the act of creating a connection is reported, in the two forms it takes: constructing a DbConnection, and taking one from a DbProviderFactory. Code that merely receives a connection is not reported - it did not create it, and it is not where the fix belongs.

How to fix it

Obtain the connection from IAdoConnectionFactory, or express the work as an IDbExecute and let Juno supply one.

Code examples

Noncompliant code example

public async Task<Order> Find(int id)
{
    using var connection = new SqlConnection(_connectionString); // Noncompliant
    return await connection.QuerySingleAsync<Order>("select * from Orders where Id = @id", new { id });
}

Compliant solution

public async Task<Order> Find(int id)
{
    await using var connection = connectionFactory.CreateConnection();
    return await connection.QuerySingleAsync<Order>("select * from Orders where Id = @id", new { id });
}
