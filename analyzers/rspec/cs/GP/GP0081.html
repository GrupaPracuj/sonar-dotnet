An instance field should not have protected accessibility.

Why is this an issue?

A protected field is visible to every derived type, in every assembly that can define one - exactly the same reach a public field has, just restricted to one particular audience instead of everyone. Sonar's own S1104 already flags public instance fields for this reason: additional behavior (validation, change notification) cannot be added later, the internal representation is exposed and locked in, and the value can be changed from any of those derived types without the declaring type having any say in it. Every one of those disadvantages applies just as much to a protected field as to a public one - the only difference is who is affected.

public class Order
{
    protected decimal Total; // any derived type can read and overwrite Total directly, bypassing any validation
}

Exceptions

This rule mirrors S1104's exact exception list:

  • Fields marked readonly or const are ignored - both close off the "changed from anywhere" concern.
  • Fields inside a type annotated with [StructLayout] are ignored - the field's exact shape is part of an intentional, explicit memory layout.
  • Fields inside a type annotated with [Serializable] are ignored, unless the field itself is annotated [NonSerialized] - a field that opts back out of serialization is treated the same as if the type were not [Serializable] at all.

Only instance fields are checked. A protected static field is a different, less contested case that this guideline does not cover. protected internal and private protected fields are also out of scope - each is a distinct accessibility level, not the plain protected this rule targets.

How to fix it

Make the field private and expose a protected property in its place. This keeps the same audience able to read and write the value, while leaving room to add validation, change the internal representation, or observe writes later without breaking derived types.

Code examples

Noncompliant code example

public class Order
{
    protected decimal Total; // Noncompliant {{'Total' should not have protected accessibility - use a protected property instead.}}
}

Compliant solution

public class Order
{
    private decimal total;

    protected decimal Total
    {
        get => total;
        set => total = value;
    }
}
