CreatedAtAction should identify an action by the name that ASP.NET Core MVC exposes for routing.

Why is this an issue?

MVC suppresses the Async suffix in action names by default. Consequently, nameof(GetAsync) evaluates to "GetAsync", while the routable action name is "Get". A CreatedAtAction response using that value may fail to generate its Location header at runtime.

The rule reports only real MVC CreatedAtAction calls that use nameof for an MVC action. It does not report when the action has an explicit matching ActionName, or when the compilation consistently disables SuppressAsyncSuffixInActionNames.

How to fix it

Give the target endpoint a named route and generate the response with CreatedAtRoute. This avoids coupling link generation to MVC's action-name transformation.

Code examples

Noncompliant code example

return CreatedAtAction(nameof(GetAsync), new { id = order.Id }, order); // Noncompliant

Compliant solution

[HttpGet("{id}", Name = "GetOrder")]
public async Task<IActionResult> GetAsync(int id) { /* ... */ }

return CreatedAtRoute("GetOrder", new { id = order.Id }, order);
