Under the GP contract policy, a contract type should not be able to reach itself through its member types.

Why is this an issue?

A cycle in the graph of declared member types does not prove that any runtime object graph contains a reference cycle. The relevant members may be null, may point to different instances, or may otherwise form an acyclic payload. Serializer behavior also depends on the serializer and its configured reference-handling options.

Even so, cyclic contract types make the permitted payload shape harder to reason about: instances can become arbitrarily deep, an actual reference cycle may require special serializer settings or fail serialization, and reference-preserving formats can introduce metadata such as $id/$ref that consumers must understand. GP therefore applies a conservative, serializer-independent policy that keeps contract type graphs acyclic and their ownership direction unambiguous.

public sealed class OrderContract
{
    public IReadOnlyList<OrderLineContract> Lines { get; init; }
}

public sealed class OrderLineContract
{
    public OrderContract Order { get; init; }   // closes the cycle
}

The issue is reported on the member through which the type reaches itself, because that is the edge to cut. Where two contracts point at each other, both members are reported - either one is a valid place to break the cycle, and the rule does not guess which side is the "parent". Cycles through collections and through single members are both found, and only contract-like types are followed, so a string or a DateTimeOffset is never part of a cycle.

How to fix it

Make the type graph acyclic. A child does not need a reference back to its parent on the wire: the consumer already has the parent, because that is what it deserialized. Where the back-reference carries real information, send an identifier instead of the object.

Code examples

Noncompliant code example

public sealed class OrderLineContract
{
    public string Sku { get; init; }
    public OrderContract Order { get; init; } // Noncompliant {{Break the cyclic contract type graph through 'Order'.}}
}

Compliant solution

public sealed class OrderLineContract
{
    public string Sku { get; init; }
    public Guid OrderId { get; init; }
}
