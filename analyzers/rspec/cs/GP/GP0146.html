Raw AI content should not be passed directly to a logger.

Why is this an issue?

A prompt or a model response can carry anything a user typed or anything the model generated from it - personal data, secrets pasted into a chat, or content shaped by a prompt injection attempt. Logging it wholesale (a ChatMessage, a ChatResponse, an AgentRunResponse, a collection of messages, or the raw .Text of a response) moves that same untrusted, potentially sensitive content into the logging pipeline, where it is typically retained far longer and accessed far more broadly than the original conversation. Metadata about the exchange - a model id, a token count, a duration, a finish reason, a request id - carries none of that risk and is unaffected by this rule.

_logger.LogInformation("Response: {Response}", response);

The rule recognizes logging through Microsoft.Extensions.Logging.ILogger extensions, Serilog, and methods generated with LoggerMessageAttribute. It reports values typed as ChatMessage, ChatResponse, AgentRunResponse, UsageContent, collections of chat messages, and the Text property of a known response. These types are matched in the Microsoft.Extensions.AI and Microsoft.Agents.AI namespaces.

Exceptions

Scalar metadata such as response.ModelId, response.Usage.TotalTokenCount, duration, finish reason, and request id is not reported.

How to fix it

Log identifying metadata only - a request id, a model id, a token count, a duration, a finish reason - instead of the message, the response object, or its raw text.

Code examples

Noncompliant code example

_logger.LogInformation("Response: {Response}", response); // Noncompliant {{Do not log this raw AI chat response directly - log only derived metadata (model id, token counts, duration, finish reason, request id).}}

Compliant solution

_logger.LogInformation("Response received, model {Model}, {Tokens} tokens", response.ModelId, response.Usage?.TotalTokenCount);
