A type that derives from Stream, or that directly implements IDictionary, should carry a name ending with the type it represents.

Why is this an issue?

The .NET naming guidelines list a small set of common base types and interfaces whose implementers should carry a matching suffix, so a reader can tell what a type does without opening its declaration or following its base list. A class ending in Stream is expected to behave like a stream; a class ending in Dictionary is expected to behave like a key-value lookup. Sonar's own attribute/EventArgs/exception naming rule already covers three entries from that table - this rule adds the two remaining ones that rule does not check: System.IO.Stream and IDictionary<TKey, TValue> (including the non-generic IDictionary).

public class MyCache : System.IO.Stream // the type behaves like a stream, but nothing in its name says so
{
}

Exceptions

The broader IEnumerable/ICollection/IList -> Collection entry from the same guideline table is deliberately not checked: fluent builders and iterator-pattern types legitimately implement IEnumerable<T> without being a "collection", so that entry carries a real false-positive risk that the two entries covered by this rule do not.

How to fix it

Rename the type so it ends with Stream or Dictionary, matching the base type or interface it implements.

Code examples

Noncompliant code example

public class MyCache : System.IO.Stream // Noncompliant {{Type 'MyCache' implements System.IO.Stream and should have a name ending in 'Stream'.}}
{
}

public class OrderData : System.Collections.Generic.IDictionary<string, Order> // Noncompliant {{Type 'OrderData' implements IDictionary and should have a name ending in 'Dictionary'.}}
{
}

Compliant solution

public class MyCacheStream : System.IO.Stream
{
}

public class OrderDataDictionary : System.Collections.Generic.IDictionary<string, Order>
{
}
