Audit timestamp columns created with FluentMigrator should use SQL Server's datetime2 type.

Why is this an issue?

datetime has a smaller date range and lower fractional-second precision than datetime2. Using it for RowCreatedAtUtc or RowUpdatedAtUtc makes the audit representation less precise and inconsistent with the HR-Soft database convention.

The rule recognizes FluentMigrator calls semantically and checks only the two standard audit column names. Other date columns and dynamically computed column names are outside its scope.

How to fix it

Replace AsDateTime() with AsDateTime2() for the reported audit column.

Code examples

Noncompliant code example

Create.Table("Candidates")
    .WithColumn("RowCreatedAtUtc").AsDateTime().NotNullable(); // Noncompliant

Compliant solution

Create.Table("Candidates")
    .WithColumn("RowCreatedAtUtc").AsDateTime2().NotNullable();
