When a caught exception is used to construct a replacement exception, the original exception should be retained as the inner exception.

Why is this an issue?

Copying only the message, stack trace or another detail discards the original exception type, structured diagnostic data and stack trace. This makes production failures harder to investigate and can obscure their root cause.

The rule reports newly thrown exceptions that use the caught exception's data without passing the caught exception itself to the constructor.

How to fix it

Use a constructor overload that accepts an inner exception and pass the caught exception to it. If no context needs to be added, use throw; to preserve the original exception and stack trace.

Code examples

Noncompliant code example

try
{
    ProcessOrder();
}
catch (Exception ex)
{
    throw new OrderException(ex.Message); // Noncompliant
}

Compliant solution

try
{
    ProcessOrder();
}
catch (Exception ex)
{
    throw new OrderException("Order processing failed.", ex);
}
