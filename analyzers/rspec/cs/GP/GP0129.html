A Dapper operation should receive the transaction that is already open for its connection.

Why is this an issue?

Dapper does not pick up an ambient transaction. An operation that omits it runs outside the transaction on its own implicit one, so it commits immediately and survives a later rollback - the method reads as one atomic unit of work but is not. Some providers do not even allow it: a command on a connection with an open transaction fails at runtime unless it enlists explicitly.

Two shapes carry a transaction. Inside an IDbExecute, Juno supplies an IDbTransaction parameter, and every Dapper operation in that method must be given it. On a connection created by IAdoConnectionFactory, a transaction begun on that connection must reach every Dapper operation issued before its commit or rollback.

The transaction can be passed either in Dapper's transaction argument or in a CommandDefinition. It must be the transaction belonging to the connection being used: one opened on a different connection does not make the work transactional, and the rule reports that case too. Operations issued after a commit or rollback are outside the transaction's lifetime and are not reported.

How to fix it

Pass the available transaction to the operation.

Code examples

Noncompliant code example

public async Task Save(CancellationToken token)
{
    await using var connection = connectionFactory.CreateConnection();
    await using var transaction = await connection.BeginTransactionAsync(token);
    await connection.ExecuteAsync(
        new CommandDefinition("update Orders set Saved = 1", cancellationToken: token)); // Noncompliant: the open transaction is not passed
    await transaction.CommitAsync(token);
}

Compliant solution

public async Task Save(CancellationToken token)
{
    await using var connection = connectionFactory.CreateConnection();
    await using var transaction = await connection.BeginTransactionAsync(token);
    await connection.ExecuteAsync(
        new CommandDefinition(
            "update Orders set Saved = 1",
            transaction: transaction,
            cancellationToken: token));
    await transaction.CommitAsync(token);
}

Noncompliant code example - inside an IDbExecute

public async Task Execute(IDbConnection connection, IDbTransaction transaction, CancellationToken token)
{
    await connection.ExecuteAsync("update Orders set Saved = 1"); // Noncompliant: Juno supplied a transaction for this connection
}

Compliant solution

public async Task Execute(IDbConnection connection, IDbTransaction transaction, CancellationToken token)
{
    await connection.ExecuteAsync("update Orders set Saved = 1", transaction: transaction);
}
