HTTP actions should declare every status they explicitly return with ProducesResponseType.

Why is this an issue?

OpenAPI generators cannot reliably infer every branch in an action. If the implementation returns a status that its metadata does not declare, generated clients and API documentation describe an incomplete protocol. Consumers then discover valid responses only in production.

The rule checks explicit MVC response factories returned directly by the action, including BadRequest, NotFound, Conflict, Ok, Created, Accepted, NoContent, constant StatusCode calls and Problem calls with a constant statusCode. It does not guess responses produced by middleware, model validation, filters or called services.

Exceptions

Actions excluded from API Explorer, actions covered by ASP.NET API conventions, and classic MVC controllers serving views are not reported. A response declaration inherited from the controller also counts. Minimal APIs are outside this rule because they use fluent Produces metadata rather than action attributes.

How to fix it

Add one ProducesResponseType attribute for every reported status.

Code examples

Noncompliant code example

[HttpGet("{id}")]
public IActionResult Get(string id)
{
    return Find(id) is { } value
        ? Ok(value)
        : NotFound(); // Noncompliant {{HTTP status 404 is returned but not declared. Add ProducesResponseType for this status.}}
}

Compliant solution

[HttpGet("{id}")]
[ProducesResponseType(StatusCodes.Status200OK)]
[ProducesResponseType(StatusCodes.Status404NotFound)]
public IActionResult Get(string id)
{
    return Find(id) is { } value ? Ok(value) : NotFound();
}
