An AI model invocation should cap the number of output tokens the model may generate.

Why is this an issue?

An unbounded (or zero/negative) output token limit lets a single call generate an arbitrarily long response, which directly drives cost and latency and can be used to exhaust a budget or a rate limit through nothing more exotic than a verbose prompt. Setting MaxOutputTokens turns "how much can this one call cost" into a reviewable, bounded number instead of an open question.

public Task<ChatResponse> Ask(string prompt) =>
    _chatClient.GetResponseAsync(prompt, new ChatOptions());

The rule recognizes IChatClient.GetResponseAsync() and GetStreamingResponseAsync() from Microsoft.Extensions.AI, including calls through implementations and extension methods. It also recognizes AIAgent.RunAsync() and RunStreamingAsync() from Microsoft.Extensions.AI and Microsoft.Agents.AI. When one of these methods has a ChatOptions parameter, the rule checks that MaxOutputTokens is set to a positive value.

Exceptions

A ChatOptions instance supplied through a parameter, field, or method call is not reported because its configuration cannot be determined at the call site. A non-constant value assigned to MaxOutputTokens is also accepted because the rule cannot prove that it is zero or negative.

How to fix it

Set MaxOutputTokens on the ChatOptions passed to the call to a positive value appropriate for the use case.

Code examples

Noncompliant code example

public Task<ChatResponse> Ask(string prompt) =>
    _chatClient.GetResponseAsync(prompt, new ChatOptions()); // Noncompliant {{Set 'MaxOutputTokens' on the ChatOptions passed to this AI model invocation to a positive value.}}

Compliant solution

public Task<ChatResponse> Ask(string prompt) =>
    _chatClient.GetResponseAsync(prompt, new ChatOptions { MaxOutputTokens = 512 });
