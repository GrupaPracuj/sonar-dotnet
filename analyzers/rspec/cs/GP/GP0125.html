Successful response metadata should describe statuses that an API action can actually return.

Why is this an issue?

Declaring a response such as 201 Created without any corresponding action path misleads OpenAPI consumers. Generated clients and tests may implement behavior that the endpoint cannot provide, while the stale declaration hides a change in the endpoint contract.

The rule compares method-level 2xx and 3xx response metadata with explicit MVC or Minimal API result factories returned by the action. It reports a status only when every returned expression is understood. Unknown helpers and dynamic status codes suppress the rule to avoid guessing. Controller-level metadata and API conventions are not reported. Error statuses are deliberately excluded because filters, middleware and exception handlers can produce them outside the action body.

How to fix it

Return the declared status from the appropriate action path, or remove the stale ProducesResponseType declaration.

Code examples

Noncompliant code example

[ProducesResponseType(typeof(OrderResponse), StatusCodes.Status201Created)] // Noncompliant
[ProducesResponseType(typeof(OrderResponse), StatusCodes.Status200OK)]
public IActionResult Create(CreateOrder request)
{
    return Ok(CreateOrder(request));
}

Compliant solution

[ProducesResponseType(typeof(OrderResponse), StatusCodes.Status201Created)]
public IActionResult Create(CreateOrder request)
{
    var order = CreateOrder(request);
    return CreatedAtAction(nameof(Get), new { id = order.Id }, order);
}
