A service address should be resolved through Juno, not by querying the Consul client directly.

Why is this an issue?

Juno owns service discovery. Naming a service - Service("orders") on the Juno HTTP client - resolves the address, applies the configured retry and timeout policy, and records the call. Reaching for IConsulClient gets you an address and nothing else, so everything Juno layers on top has to be rebuilt by hand at each call site: the health filter, the choice between instances, the cache lifetime, the failure behaviour when the catalog is briefly unavailable.

The consequences show up under exactly the conditions discovery exists for. Code that takes the first entry from the catalog sends all traffic to one instance, so scaling out changes nothing. Code that caches the address without a lifetime keeps calling an instance that has since been drained. Neither fails in a test - both fail during a deployment.

var services = await _consul.Catalog.Service("orders");
var address = services.Response[0].ServiceAddress;
var response = await _httpClient.GetStringAsync($"http://{address}/orders");

Registration and health checks are a separate matter: in a GP service they are configured by Juno's host, not written per service, so AgentServiceRegistration appearing in application code is itself the signal that something is being done twice.

Exceptions

Types under the GP.Juno namespaces are not reported - that is where the Consul client belongs, since Juno is what wraps it. Locking on Consul is covered separately by GP0040.

How to fix it

Name the service and let Juno resolve it.

Code examples

Noncompliant code example

public async Task<string> GetOrders()
{
    var services = await _consul.Catalog.Service("orders"); // Noncompliant {{Resolve the service through Juno instead of querying 'IConsulClient' directly.}}
    var address = services.Response[0].ServiceAddress;
    return await _httpClient.GetStringAsync($"http://{address}/orders");
}

Compliant solution

public Task<string> GetOrders() =>
    _builder.Service("orders").AddPath("orders").GetJson<string>();
