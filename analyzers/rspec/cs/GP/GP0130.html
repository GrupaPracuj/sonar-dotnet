A Dapper operation on a Juno connection should pass the caller's CancellationToken through a CommandDefinition.

Why is this an issue?

Dapper's convenience overloads take no token, so a query started through them cannot be cancelled. When the caller goes away - the HTTP request is aborted, a timeout fires, the host shuts down - the query keeps running and holds its connection until the database finishes it. Under load these abandoned queries accumulate and exhaust the connection pool, which turns one slow client into a service-wide outage.

Passing CancellationToken.None or default has the same effect as passing nothing and is reported as well. A command built elsewhere and handed to the operation is not inspected, because the token may already be inside it.

The rule applies to Dapper operations on a connection created by IAdoConnectionFactory. Work expressed as an IDbExecute, or as any method a runner hands both the connection and the transaction, is out of scope: there the runner owns the command's lifetime.

Nothing is reported unless a CancellationToken is actually in scope - a parameter of the method, or of an enclosing method when the call sits in a lambda or local function. A method that receives no token cannot pass one on, and its signature may be fixed by the interface it implements, so asking would be advice it could not act on.

How to fix it

Build a CommandDefinition and give it the token the method received.

Code examples

Noncompliant code example

public async Task<Order> Find(int id, CancellationToken token)
{
    await using var connection = connectionFactory.CreateConnection();
    return await connection.QuerySingleAsync<Order>(
        "select * from Orders where Id = @id", new { id }); // Noncompliant: the token is dropped
}

Compliant solution

public async Task<Order> Find(int id, CancellationToken token)
{
    await using var connection = connectionFactory.CreateConnection();
    return await connection.QuerySingleAsync<Order>(
        new CommandDefinition("select * from Orders where Id = @id", new { id }, cancellationToken: token));
}
