A consumer should await everything it starts, so the broker only sees the message as handled once the work is actually done.

Why is this an issue?

The broker's contract with a consumer is the returned task. When Consume completes, the message is acknowledged and removed - so any work that is still running at that moment has lost the only safety net it had. If it then fails, there is no redelivery, no error queue and no exception anyone sees: the message was already acknowledged as successfully handled.

Fire-and-forget work also outlives the scope it was started in. The ConsumeContext is disposed when Consume returns, taking the scoped dependency-injection container with it, so a DbContext captured by the abandoned task is disposed underneath it. During shutdown it is worse: the host stops, and work that nothing is awaiting is simply killed mid-flight.

public Task Consume(ConsumeContext<OrderAccepted> context)
{
    _ = ProcessAsync(context.Message);            // nothing awaits this
    Task.Run(() => Notify(context.Message));      // nor this
    return Task.CompletedTask;                     // message acknowledged immediately
}

The rule reports, inside a consumer, a call that returns a Task or ValueTask and is neither awaited nor returned - whether it is discarded with _ =, left as a bare expression statement, or wrapped in Task.Run.

Exceptions

async void is not reported here: S3168 reports it already, on every method rather than only in consumers.

A task that is stored, passed on, or later awaited through a variable is not reported, since the work is still tracked by something.

How to fix it

Await the work, or return its task. If it genuinely must happen out of band, publish a message for it so the broker keeps the guarantee instead of dropping it.

Code examples

Noncompliant code example

public Task Consume(ConsumeContext<OrderAccepted> context)
{
    _ = ProcessAsync(context.Message); // Noncompliant {{Await this call - the message is acknowledged when Consume returns, so work nothing awaits is lost without a trace.}}
    return Task.CompletedTask;
}

Compliant solution

public Task Consume(ConsumeContext<OrderAccepted> context) =>
    ProcessAsync(context.Message);
