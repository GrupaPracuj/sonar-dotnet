Do not start asynchronous work in a message consumer and then finish Consume without waiting for that work.

Why is this an issue?

MassTransit considers a message handled when the Task returned by Consume completes. It can then acknowledge the message and remove it from the queue.

If Consume calls an asynchronous method without awaiting or returning its task, these two operations become disconnected:

  1. The asynchronous operation starts.
  2. Consume returns before that operation finishes.
  3. MassTransit acknowledges the message as successfully handled.
  4. The operation may fail afterwards, but the message will not be retried or moved to the error queue.

This is commonly called fire-and-forget. It is particularly unsafe in a consumer because the abandoned task may also use scoped objects such as a DbContext after the consumer scope has been disposed, or be interrupted during application shutdown.

public Task Consume(ConsumeContext<OrderAccepted> context)
{
    _ = SaveOrderAsync(context.Message); // asynchronous work starts
    return Task.CompletedTask;            // Consume finishes before SaveOrderAsync
}

The rule reports a call inside a MassTransit consumer when all of the following are true:

  • the call returns Task, Task<T>, ValueTask or ValueTask<T>;
  • the call is written as a standalone statement, such as SaveOrderAsync(message);, or explicitly discarded with _ = SaveOrderAsync(message);;
  • the task is therefore neither awaited nor returned from Consume.

Exceptions

A task returned directly from Consume is compliant: MassTransit awaits that task. Assigning a task to a named variable is not reported either, because it may be awaited later. Calls returning void and code outside a consumer are outside this rule.

async void is handled by rule S3168.

How to fix it

Await the operation before completing Consume, or return its task directly. This keeps message acknowledgement, retries and the consumer lifetime tied to the actual work.

If the operation intentionally needs an independent lifetime, publish a separate message for it instead of starting an untracked task.

Code examples

Noncompliant code example

public Task Consume(ConsumeContext<OrderAccepted> context)
{
    _ = SaveOrderAsync(context.Message); // Noncompliant {{Await this call - the message is acknowledged when Consume returns, so work nothing awaits is lost without a trace.}}
    return Task.CompletedTask;
}

Compliant solution

public Task Consume(ConsumeContext<OrderAccepted> context) =>
    SaveOrderAsync(context.Message);
