A contract should not expose a database query or asynchronous sequence for the serializer to execute.

Why is this an issue?

IQueryable<T> carries a query provider and expression tree rather than a completed result. If it is placed on a contract, the serializer executes the query while enumerating the property. This happens outside the code that built the response or message; a disposed DbContext then causes serialization to fail, while a live context performs database work at an unexpected boundary.

IAsyncEnumerable<T> likewise represents work that happens while its items are consumed and is not a stable, already-produced payload.

A materialized read-only collection removes the question: the items exist, the count is known, and enumerating it again is free and identical.

namespace GP.Orders.Contracts;

public sealed class OrderAccepted
{
    public IQueryable<OrderLine> Lines { get; init; }
}

What is considered a contract?

The rule does not infer a contract from the type's name. A type is considered a contract when at least one of the following is true:

  • it is declared directly in a namespace named Contracts or ending in .Contracts, such as GP.Orders.Contracts;
  • it is returned from an ASP.NET controller action or Minimal API endpoint, including responses wrapped in Task<T>, ValueTask<T> or ActionResult<T>, and payloads passed to standard MVC, Results or TypedResults response factories;
  • it is published or sent through GP.Juno or MassTransit using Publish, PublishBatch, Send, RespondAsync, Publishes or Sends.

A similarly named method on an unrelated application type does not make its argument a contract.

Exceptions

IEnumerable<T> is not reported merely because its interface permits deferred execution. It commonly contains an already materialized list, and the declaration alone cannot prove otherwise. IReadOnlyCollection<T>, IReadOnlyList<T>, arrays and concrete collections are also not reported.

How to fix it

Declare the property as IReadOnlyList<T> or IReadOnlyCollection<T> and materialize the sequence when the message is built.

Code examples

Noncompliant code example

namespace GP.Orders.Contracts;

public sealed class OrderAccepted
{
    public IQueryable<OrderLine> Lines { get; init; } // Noncompliant {{'Lines' exposes a deferred query or asynchronous sequence; materialize it as IReadOnlyList before serialization.}}
}

Compliant solution

namespace GP.Orders.Contracts;

public sealed class OrderAccepted
{
    public IReadOnlyList<OrderLine> Lines { get; init; }
}
