A URL that arrives as a parameter of a controller action should not be passed directly to an outbound HTTP call.

Why is this an issue?

When the destination of a server-side request is chosen by the caller, the caller decides what your service connects to. MITRE describes the weakness as:

The web server receives a URL or similar request from an upstream component and retrieves the contents of this URL, but it does not sufficiently ensure that the request is being sent to the expected destination.

This matters more inside a service mesh than on a developer machine. The request leaves from inside your network, so it reaches things the original caller never could: another service's internal endpoint, an admin port bound to localhost, or a cloud metadata endpoint that hands out credentials to anything that asks. Firewalls and network policies do not help, because from their point of view the request is your service making a perfectly normal call.

The OWASP SSRF Prevention Cheat Sheet is direct about the input itself:

Do not accept complete URLs from the user because URL are difficult to validate and the parser can be abused. 
[HttpGet("preview")]
public async Task<IActionResult> Preview(string imageUrl)
{
    var content = await _httpClient.GetStringAsync(imageUrl);
    return Ok(content);
}

This rule reports a value the model binder filled from the route, the query string or the body when that value can still steer where the request goes - it is the whole URL, or it lands in the part of the URL that decides the host. An identifier substituted into a path segment of an address whose host is already fixed in the code, such as $"{_options.ImageServiceBaseUrl}/images/{imageId}", picks which resource is fetched rather than which server answers, and is not reported.

It also does not follow a value through local variables, fields or other methods, so a URL that takes a longer path to the same call is not reported - the absence of an issue here is not proof that the code is free of this weakness.

How to fix it

Do not let the caller name the destination. Take an identifier instead of a URL and build the address yourself, or - when a URL genuinely has to be accepted - resolve its host and compare it against an allowlist of trusted hosts before the request is made. The OWASP guidance is:

Build an allowlist with all the domain names of every identified and trusted applications. Verify that the domain name received is part of this allowlist (string strict comparison with case sensitive).

Code examples

Noncompliant code example

[HttpGet("preview")]
public async Task<IActionResult> Preview(string imageUrl)
{
    var content = await _httpClient.GetStringAsync(imageUrl); // Noncompliant {{Do not send a request to a URL taken from parameter 'imageUrl' - validate the host against an allowlist first.}}
    return Ok(content);
}

Compliant solution

Accept an identifier and build the URL from configuration you control:

[HttpGet("preview")]
public async Task<IActionResult> Preview(Guid imageId)
{
    var content = await _httpClient.GetStringAsync($"{_options.ImageServiceBaseUrl}/images/{imageId}");
    return Ok(content);
}

Or, when a URL has to be accepted, check its host against an allowlist first:

[HttpGet("preview")]
public async Task<IActionResult> Preview(string imageUrl)
{
    if (!Uri.TryCreate(imageUrl, UriKind.Absolute, out var uri)
        || !_options.AllowedImageHosts.Contains(uri.Host, StringComparer.Ordinal))
    {
        return BadRequest();
    }

    var content = await _httpClient.GetStringAsync(uri);
    return Ok(content);
}
