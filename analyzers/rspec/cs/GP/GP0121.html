A joined SQL Server DELETE should use FROM, not accidentally start a separate SELECT statement.

Why is this an issue?

In DELETE target SELECT ... FROM ... WHERE ..., the WHERE belongs to the SELECT. The preceding DELETE target therefore deletes every row. This typo is especially dangerous in purge code, where the query still looks visually filtered.

To avoid false positives for deliberate full-table operations, the rule reports only this narrow malformed shape. It does not report a general DELETE without WHERE, nor explicitly separated statements.

How to fix it

Replace the accidental SELECT with FROM so the join and predicate form one DELETE statement.

Noncompliant code example

const string Sql = """
    DELETE schOffers.tCommonOffersInheritance
    SELECT coi.* FROM schOffers.tCommonOffersInheritance coi
    WHERE coi.companyID = @companyId
    """; // Noncompliant

Compliant solution

const string Sql = """
    DELETE coi
    FROM schOffers.tCommonOffersInheritance coi
    WHERE coi.companyID = @companyId
    """;
