A whole contract object should not be passed to a logger.

Why is this an issue?

Logging the object logs every field it has now, and every field anybody adds to it later. That is the problem: the decision about what ends up in the log is made once, by whoever wrote the log line, and then silently re-made by every future change to the contract. A field added months later for an unrelated reason - an email address, a national ID, a token - starts appearing in the log with no code change at that call site and no review of the consequence.

MITRE describes the resulting weakness as "Insertion of Sensitive Information into Log File", and logs are a poor place to discover it: they are shipped to aggregation services, retained on a different schedule from the data itself, and readable by a wider group than the payload ever was.

It is also worse diagnostically than it looks. A serialized contract in a message template produces one large unsearchable string rather than the few indexed fields the investigation actually needs.

_logger.LogInformation("Received {Message}", message);   // whatever the contract carries, now and later

The rule reports a logging argument whose type is a contract - the same naming convention the other contract rules use. It looks at the type of the whole argument, so passing individual fields is never reported no matter what those fields are called, and what gets interpolated into the message template is outside what this rule inspects.

How to fix it

Log the few fields the diagnosis needs, named as template placeholders so they stay queryable. An identifier and a status are usually enough to find the message itself if more is required.

Code examples

Noncompliant code example

public Task Consume(ConsumeContext<OrderAcceptedContract> context)
{
    _logger.LogInformation("Received {Message}", context.Message); // Noncompliant {{Do not log the whole contract 'OrderAcceptedContract' - log the fields the diagnosis needs.}}
    return Task.CompletedTask;
}

Compliant solution

public Task Consume(ConsumeContext<OrderAcceptedContract> context)
{
    _logger.LogInformation("Received order {OrderId} with status {Status}", context.Message.OrderId, context.Message.Status);
    return Task.CompletedTask;
}
