Converting a nullable integral value with Convert.ToInt32 or Convert.ToInt64 should handle null explicitly.

Why is this an issue?

These methods bind a nullable argument to an overload that accepts object. When the nullable has no value, boxing produces null, and Convert silently returns zero. A missing identifier can therefore become the valid-looking identifier 0 instead of remaining absent or causing the intended validation failure.

The rule reports only nullable integral values passed directly to System.Convert.ToInt32 or System.Convert.ToInt64. It does not infer identifier semantics or prescribe whether the application should use zero, reject the value, or preserve nullability.

How to fix it

State the null policy before conversion. Use ?? 0 when zero is intentional, access Value when absence is invalid, or keep the result nullable.

Code examples

Noncompliant code example

int ToId(int? sourceId) =>
    Convert.ToInt32(sourceId); // Noncompliant

Compliant solution

int ToId(int? sourceId) =>
    Convert.ToInt32(sourceId ?? 0);
