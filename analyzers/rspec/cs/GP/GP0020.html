Every action in a controller should explicitly state whether it requires authorization, once other actions in the same controller already do.

Why is this an issue?

When some actions in a controller carry [Authorize] and others don't, the missing declaration is ambiguous: it might be an intentionally public endpoint, or it might be an endpoint that was simply forgotten when access control was added to the rest of the controller. Making the omission explicit with [AllowAnonymous] removes that ambiguity - a reviewer (and the next person to touch the file) can tell at a glance that the endpoint is public on purpose, not by oversight.

public class UsersController : ControllerBase
{
    [Authorize]
    public IActionResult GetProfile() { /* ... */ }

    public IActionResult GetSettings() { /* ... */ } // no [Authorize], no [AllowAnonymous] - intentional?
}

Exceptions

The rule only compares actions within the same controller class. A controller where no action uses [Authorize] at all is not checked - there is no established convention in that controller to be inconsistent with. A controller (or the specific action) already carrying [Authorize] or [AllowAnonymous] at the class level is not checked either, since in that case every action already inherits an explicit default.

How to fix it

Add [Authorize] if the endpoint should require authorization, or [AllowAnonymous] if it is meant to stay public.

Code examples

Noncompliant code example

public class UsersController : ControllerBase
{
    [Authorize]
    public IActionResult GetProfile() { /* ... */ }

    public IActionResult GetSettings() { /* ... */ } // Noncompliant {{Method 'GetSettings' has neither [Authorize] nor [AllowAnonymous], but other actions in 'UsersController' are explicitly protected with [Authorize].}}
}

Compliant solution

public class UsersController : ControllerBase
{
    [Authorize]
    public IActionResult GetProfile() { /* ... */ }

    [AllowAnonymous]
    public IActionResult GetSettings() { /* ... */ }
}
