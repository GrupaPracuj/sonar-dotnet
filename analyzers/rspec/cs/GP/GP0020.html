Every REST API action should explicitly state whether it requires authorization. Classic MVC controllers are checked when sibling actions establish a per-action [Authorize] convention.

Why is this an issue?

When some actions in a controller carry [Authorize] and others don't, the missing declaration is ambiguous: it might be an intentionally public endpoint, or it might be an endpoint that was simply forgotten when access control was added to the rest of the controller. Making the omission explicit with [AllowAnonymous] removes that ambiguity - a reviewer (and the next person to touch the file) can tell at a glance that the endpoint is public on purpose, not by oversight.

Controllers marked with [ApiController] on the type, a base type, or the assembly are held to a stricter default: every action must have [Authorize] or [AllowAnonymous], unless the compilation directly configures an authenticated fallback policy, adds the ASP.NET Core MVC AuthorizeFilter globally, or applies RequireAuthorization() directly to MapControllers().

public class UsersController : ControllerBase
{
    [Authorize]
    public IActionResult GetProfile() { /* ... */ }

    public IActionResult GetSettings() { /* ... */ } // no [Authorize], no [AllowAnonymous] - intentional?
}

Exceptions

A classic MVC controller where no action uses [Authorize] is not checked. A controller or base controller carrying [Authorize] or [AllowAnonymous] already declares the default for its actions. The rule also accepts directly detectable global protection: assignment to AuthorizationOptions.FallbackPolicy whose policy construction calls RequireAuthenticatedUser(), adding the framework's Microsoft.AspNetCore.Mvc.Authorization.AuthorizeFilter to MVC's global filter collection, or MapControllers().RequireAuthorization(). Merely calling AddAuthorization, configuring a named policy, application conventions, or unrelated lookalike types does not provide sufficiently strong evidence and is not treated as global protection.

How to fix it

Add [Authorize] if the endpoint should require authorization, or [AllowAnonymous] if it is meant to stay public.

Code examples

Noncompliant code example

public class UsersController : ControllerBase
{
    [Authorize]
    public IActionResult GetProfile() { /* ... */ }

    public IActionResult GetSettings() { /* ... */ } // Noncompliant {{Method 'GetSettings' has neither [Authorize] nor [AllowAnonymous], but other actions in 'UsersController' are explicitly protected with [Authorize].}}
}

Compliant solution

public class UsersController : ControllerBase
{
    [Authorize]
    public IActionResult GetProfile() { /* ... */ }

    [AllowAnonymous]
    public IActionResult GetSettings() { /* ... */ }
}
