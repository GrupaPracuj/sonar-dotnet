An HTTP client should be obtained from Juno, not constructed with new HttpClient(), new WebClient(), WebRequest.Create(...) or IHttpClientFactory.CreateClient(...).

Why is this an issue?

Every outbound call from a GP service is expected to go through Juno's HttpApiClient. That is not a stylistic preference: it is where service discovery, the retry and timeout policy, the propagated correlation headers, the authentication handler and the outgoing-call metrics live. A hand-rolled client reaches the same endpoint while quietly opting out of all of it, so the call is invisible in tracing, ignores the configured timeouts, and resolves addresses by whatever string happened to be at hand instead of through discovery.

A directly constructed client also brings the connection-management problem that Microsoft warns about:

To avoid port exhaustion problems, we recommend reusing HttpClient instances for as many HTTP requests as possible.
If you don't use the factory and instead create a new client instance for each request yourself, you can exhaust available ports.

Note that Microsoft's guidance stops at "reuse the instance" - a long-lived static HttpClient is acceptable as far as the framework is concerned. This rule is stricter on purpose, because the point is not only connection reuse but going through the one client that carries the cross-cutting behavior every GP service is expected to have.

public class OrderClient
{
    private readonly HttpClient _client = new HttpClient();

    public Task<string> GetOrder(string id) =>
        _client.GetStringAsync($"https://orders.internal/orders/{id}");
}

Types such as HttpResponseMessage, HttpMethod and HttpContent are not reported - the Juno client hands them back and they legitimately flow through service code. Only acquiring a client of your own is.

Exceptions

new HttpClient() inside the body of a controller action is left to rule S6962, which reports exactly that shape; reporting it here as well would put two issues on one line. A client created in a controller's field initializer or constructor - which S6962 does not report - is still reported here.

The implementation of Juno itself is not reported: its HTTP abstraction necessarily creates the framework client that consuming applications are required to obtain through Juno.

How to fix it

Inject IHttpSenderFactory and send through the HttpSender it creates. The name given to Create is the name the client is registered under - the key in the HOCON httpClient.services block that AddConfiguredHttpApiClients(configuration) reads - so the address, discovery, authentication, retry and timeout come from configuration instead of from the call site. Build the URL with AppendPathSegments, dispose the sender, and pass the caller's CancellationToken rather than CancellationToken.None.

GetJson and its siblings do not check the response status - they deserialize whatever came back - so decide what a failure means: ThrowWhenNotSuccessStatusCode with your own message when any non-2xx is a fault, or HttpSenderResponse and ReceiveJson<T> when a status such as 404 is a domain answer.

Do not reach for GP.Juno.HttpClient - IHttpClientBuilder, IHttpClient, HttpClientConfigurator, UseHttpClient. That is the previous HTTP stack, the whole namespace carries [Obsolete], and HttpApiClient supersedes it.

Code examples

Noncompliant code example

public class OrderClient
{
    private readonly HttpClient _client = new HttpClient(); // Noncompliant {{Obtain the HTTP client from Juno (IHttpSenderFactory.Create(...)) instead of creating 'HttpClient' directly.}}

    public Task<string> GetOrder(string id) =>
        _client.GetStringAsync($"https://orders.internal/orders/{id}");
}

Compliant solution

public sealed class OrderClient(IHttpSenderFactory senderFactory)
{
    private const string ClientName = "orders";

    public async Task<Order?> GetOrder(string id, CancellationToken cancellation)
    {
        using var sender = senderFactory.Create(ClientName);

        return await sender
            .AppendPathSegments("orders", id)
            .ThrowWhenNotSuccessStatusCode($"Could not fetch order {id}")
            .GetJson<Order>(cancellation);
    }
}
