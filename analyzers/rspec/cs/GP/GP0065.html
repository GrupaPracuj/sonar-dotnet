Domain code should not reference the message bus, HTTP or the web framework.

Why is this an issue?

The domain is the part of the service that should still make sense if the transport changed. Once a domain type mentions ConsumeContext, IPublishEndpoint, HttpResponseMessage or HttpContext, that stops being true: the rules of the business can no longer be read, tested or reused without a broker and a web host in scope.

The practical cost shows up first in tests. A domain method that takes a transport type needs that type constructed to be exercised at all, so the cheapest tests in the codebase - the ones over business rules - acquire the slowest dependencies. It shows up next in change: a transport upgrade now touches domain files, and a domain refactor now has to keep the transport compiling.

Microsoft's layering guidance puts the dependency in the opposite direction, and states the goal for the model plainly:

Clean architecture puts the business logic and application model at the center of the application. Instead of having business logic depend on data access or other infrastructure concerns, this dependency is inverted. 
namespace MyCompany.Orders.Domain;

public sealed class Order
{
    public void Accept(ConsumeContext<OrderRequested> context) { /* ... */ }
}

Exceptions

The rule reports code whose namespace matches domainNamespaces or whose assembly name matches domainAssemblyNames (default Domain), so it stays out of application and infrastructure code, where these types belong. The forbiddenNamespaces parameter defaults to the transport and web namespaces - MassTransit, RabbitMQ.Client, Microsoft.AspNetCore, System.Net.Http and Juno's messaging and HTTP abstractions.

How to fix it

Keep the transport out of the signature. Let the consumer or the controller unpack the message and call the domain with plain values, and have the domain return a result the caller translates back.

Code examples

Noncompliant code example

namespace MyCompany.Orders.Domain;

public sealed class Order
{
    public void Accept(ConsumeContext<OrderRequested> context) { } // Noncompliant {{'ConsumeContext' comes from 'MassTransit', which domain code should not depend on.}}
}

Compliant solution

namespace MyCompany.Orders.Domain;

public sealed class Order
{
    public void Accept(Guid customerId, DateTimeOffset acceptedAt) { }
}
