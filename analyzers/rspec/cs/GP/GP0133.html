A class implementing Juno's IDbExecute or ITransactional belongs in the data access project, not in an assembly whose name ends with .Api.

Why is this an issue?

A persistence operation carries the SQL, the table names and the shape of a row. Declared next to the endpoints, it puts all of that in the assembly whose job is HTTP, and every consumer of the same data either references the API assembly to reuse it or writes the query a second time. The second copy is the usual outcome, and the two drift: one remembers the soft-delete filter, the other does not.

It also decides what can be tested without a database, and what a change to the schema costs. A query that lives in the data access project is reachable from a background service, a consumer and a second API alike, and a column rename is chased through one project rather than through whichever assemblies happened to declare their own operations.

The rule reports the declaration of a concrete class implementing GP.Juno.Abstractions.Ado.IDbExecute or Juno's transactional interface, in a compilation whose assembly name ends with .Api. Abstract base operations are left alone: what they are depends on the classes deriving from them. Using such an operation from transport code is a separate question, and the subject of GP0032.

How to fix it

Move the operation to the project that owns data access, and let the API assembly depend on it.

Code examples

Noncompliant code example

// GP.Shop.Api/Orders/GetOrderQuery.cs
public sealed class GetOrderQuery(int orderId) : IDbExecute<Order> // Noncompliant
{
    public Task<Order> Execute(IDbConnection connection, IDbTransaction transaction = null) =>
        connection.QuerySingleAsync<Order>("select * from Orders where Id = @orderId", new { orderId });
}

Compliant solution

// GP.Shop.DataAccess/Orders/GetOrderQuery.cs
public sealed class GetOrderQuery(int orderId) : IDbExecute<Order>
{
    public Task<Order> Execute(IDbConnection connection, IDbTransaction transaction = null) =>
        connection.QuerySingleAsync<Order>("select * from Orders where Id = @orderId", new { orderId });
}
