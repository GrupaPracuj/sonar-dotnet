Why is this an issue?

An action behind [Authorize] or a global MVC AuthorizeFilter can answer 401 Unauthorized, and - when the authorization names a policy or a role - also 403 Forbidden. Those responses are produced by the authorization middleware, not by a return statement in the action, so nothing in the method body reveals them.

Because they are invisible in the body, they are also missing from the generated OpenAPI document unless somebody adds ProducesResponseType by hand. Consumers generating clients from that document get no branch for "your token expired" or "you may not do this", and typically surface an authorization failure as an unexplained deserialization error against the success schema.

This is exactly the gap rules that inspect returned statuses cannot close: they only see what the action itself returns.

What is the potential impact?

Generated clients and API documentation silently omit the authorization failure contract of a protected endpoint.

How to fix it

Declare the responses the action's authorization can produce. Add 401 for any authorization requirement, and 403 as well when a policy or a role is named. An attribute may sit on the action or controller; a global AuthorizeFilter registered in MVC options is also honoured.

Noncompliant code example

[ApiController]
[Authorize(Policy = "RoleReadAccess")]
public class RoleDefinitionsController : ControllerBase
{
    [HttpGet("roles")]
    [ProducesResponseType(typeof(GetRoleDefinitionsResponse), StatusCodes.Status200OK)]
    public IActionResult GetRoleDefinitions() => Ok(definitions); // Noncompliant: 401 and 403 are reachable but undeclared
}

Compliant solution

[ApiController]
[Authorize(Policy = "RoleReadAccess")]
public class RoleDefinitionsController : ControllerBase
{
    [HttpGet("roles")]
    [ProducesResponseType(typeof(GetRoleDefinitionsResponse), StatusCodes.Status200OK)]
    [ProducesResponseType(StatusCodes.Status401Unauthorized)]
    [ProducesResponseType(StatusCodes.Status403Forbidden)]
    public IActionResult GetRoleDefinitions() => Ok(definitions);
}
