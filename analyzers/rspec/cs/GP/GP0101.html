Every HTTP action should explain what it does to OpenAPI consumers.

Why is this an issue?

A route and method name rarely communicate the action's behavior, authorization assumptions and important side effects well enough for a generated API reference. Without operation documentation, consumers have to read the implementation or reverse-engineer the endpoint.

The rule accepts a non-empty Swashbuckle SwaggerOperation summary or description, native EndpointSummary/EndpointDescription metadata, or an XML summary or remarks - including one inherited through <inheritdoc>. It therefore enforces documentation without forcing one OpenAPI library.

Exceptions

Actions excluded from API Explorer and classic MVC controllers serving views are not part of the generated API and are not reported. Minimal APIs are outside this rule because their metadata is attached to route builders rather than action methods.

How to fix it

Add a concise operation summary or description that states the action's observable purpose.

Code examples

Noncompliant code example

[HttpPost]
public IActionResult Create(CreateOrder request) // Noncompliant {{Describe this HTTP action for OpenAPI consumers.}}
{
    // ...
}

Compliant solution

/// <summary>Creates an order and returns its public identifier.</summary>
[HttpPost]
public IActionResult Create(CreateOrder request)
{
    // ...
}
