A command contract registered for sending should express intent and should not use the technical Command suffix.

Why is this an issue?

A command represents an intent: a request for something to happen (AcceptOrder, ShipPackage). Once the type is sent through the messaging infrastructure, its role as a command is already clear from that context, so appending the technical suffix Command to its name (AcceptOrderCommand) is redundant noise that doesn't add any information for the reader.

public class AcceptOrderCommand { }

appConfig.Sends<AcceptOrderCommand>();

How to fix it

Rename the command type to an imperative name that expresses the requested action, without the technical suffix.

Code examples

Noncompliant code example

public class AcceptOrderCommand { }

public static class Startup
{
    public static void RegisterMessages(AppConfig appConfig) =>
        appConfig.Sends<AcceptOrderCommand>(); // Noncompliant {{Rename command 'AcceptOrderCommand' to remove the 'Command' suffix.}}
}

Compliant solution

public class AcceptOrder { }

public static class Startup
{
    public static void RegisterMessages(AppConfig appConfig) =>
        appConfig.Sends<AcceptOrder>();
}
