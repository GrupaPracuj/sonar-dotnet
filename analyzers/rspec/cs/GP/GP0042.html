A volatile field should not be updated by reading and writing it back - use Interlocked or a lock instead.

Why is this an issue?

Marking a field volatile is easily read as "this field is now safe to touch from several threads". It is not. Microsoft's C# reference states the limit plainly:

The volatile keyword doesn't provide atomicity for operations other than assignment. It doesn't prevent race conditions, and it doesn't provide ordering guarantees for other memory operations.

counter++ is not an assignment. It is a read, an add and a write, and two threads can interleave those steps so that both read the same value and both write the same result - one increment is simply lost. The same applies to counter += 1 and to counter = counter + 1. The bug is invisible under light load and shows up as counters that drift low under real traffic, which makes it one of the harder failures to reproduce and one of the easier ones to prevent.

private volatile int _processed;

public void Process(Order order)
{
    Handle(order);
    _processed++;
}

The declaration itself is the signal that this field is shared, which is what makes a non-atomic update on it worth reporting rather than merely suspicious.

Exceptions

A plain assignment of a value that does not depend on the field's current value (_shouldStop = true) is exactly what volatile does guarantee, and is not reported.

How to fix it

Use Interlocked.Increment/Add/Exchange for a numeric counter, or take a lock if the update is part of a larger critical section. Microsoft recommends this generally, not only for compound updates: "For most multithreaded scenarios, even with supported types, prefer using Interlocked operations, lock statements, or other synchronization primitives instead of volatile."

Code examples

Noncompliant code example

private volatile int _processed;

public void Process(Order order)
{
    Handle(order);
    _processed++; // Noncompliant {{'_processed' is volatile, which does not make this update atomic - use Interlocked or a lock.}}
}

Compliant solution

private int _processed;

public void Process(Order order)
{
    Handle(order);
    Interlocked.Increment(ref _processed);
}
