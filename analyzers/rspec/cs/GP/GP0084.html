[ThreadStatic] has no effect unless the field it decorates is also static.

Why is this an issue?

ThreadStaticAttribute only changes the storage of a static field, giving each thread its own independent copy instead of one copy shared by all threads. The CLR ignores it entirely on an instance field: an instance field already has one copy per object, so there is nothing for the attribute to change, and the field goes on behaving as an ordinary shared-per-instance field. The result is code that reads as if it were designed for per-thread isolation - the attribute is right there - but actually is not, and the mismatch is invisible until two threads that happen to share the same instance start stepping on each other's value.

public class RequestContext
{
    [ThreadStatic]
    private int _requestId; // does nothing: every thread that touches this instance shares the same field
}

How to fix it

Decide what was actually intended, since the two fixes lead to different behavior:

  • Add static to get genuine per-thread storage. Every instance of the type then shares that one field, one copy per thread - which is usually what "thread-static" is meant to provide.
  • Remove the attribute to keep the current, working, per-instance behavior, if per-thread isolation was never actually needed.

Code examples

Noncompliant code example

public class RequestContext
{
    [ThreadStatic]
    private int _requestId; // Noncompliant {{'_requestId' has 'System.ThreadStaticAttribute' but is not static - the attribute has no effect on instance fields.}}
}

Compliant solution

public class RequestContext
{
    [ThreadStatic]
    private static int _requestId;
}
