A controller action should not return a database entity or an IQueryable.

Why is this an issue?

Returning the entity makes the database schema the API contract. A column added for internal bookkeeping appears in the response; a column renamed during a refactor silently breaks every client. Worse, it leaks whatever the entity happens to carry - an IsDeleted flag, an internal cost, a password hash - because nobody chose what to expose, the mapper simply serialized everything public.

Returning IQueryable<T> is a sharper version of the same problem: the query has not run yet when the action returns, so it executes during serialization, outside the action's error handling and after the scope that owned the DbContext may have been disposed. Whatever the serializer touches becomes a database query, which is how a single endpoint turns into hundreds of round trips.

[HttpGet("{id}")]
public async Task<Order> Get(int id) =>
    await _context.Orders.FirstAsync(x => x.Id == id);

A type is treated as an entity only on deterministic signals: membership of a DbSet<T>, EF mapping attributes, or inheritance from one of the types explicitly named by the entityBaseTypes parameter. A namespace alone is not evidence that a type is persisted.

For MVC actions, both strongly typed return declarations and entity payloads passed to the official controller result factories such as Ok, Json, Created, Accepted, NotFound and StatusCode are checked. This covers actions declared as IActionResult without treating same-named application methods as framework results.

For Minimal APIs, the rule checks only inline handlers registered by the official MapGet, MapPost, MapPut, MapPatch and MapDelete extensions. It reports an entity passed directly to official Results.Ok, TypedResults.Ok, Results.Json or TypedResults.Json, including entity collections and IQueryable payloads. It does not infer arbitrary direct returns, follow named handlers, or inspect nested lambdas and local functions.

How to fix it

Return a response contract and map the entity onto it, choosing explicitly what the API exposes.

Code examples

Noncompliant code example

[HttpGet("{id}")]
public async Task<Order> Get(int id) => // Noncompliant {{'Order' is a database entity - return a response contract instead.}}
    await _orders.FindAsync(id);

Compliant solution

public sealed record OrderResponse(Guid Id, string CustomerReference, decimal TotalAmount, string Currency);

[HttpGet("{id}")]
public async Task<OrderResponse> Get(int id)
{
    var order = await _orders.FindAsync(id);
    return new OrderResponse(order.PublicId, order.Customer.Reference, order.Total, order.Currency);
}
