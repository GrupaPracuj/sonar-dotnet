A wire contract (a request/response DTO, or a message contract) should not declare a property of a type that doesn't survive JSON serialization.

Why is this an issue?

System.Text.Json and Newtonsoft.Json can only serialize data - a Stream, a Task, a delegate (Action/Func<...>) or an IntPtr describes a runtime operation or a process-local handle, not a value that means anything on the other side of an HTTP call or a message queue. Depending on the serializer and the exact type, this either throws at serialization time or silently produces an empty object - both cases are usually discovered much later than when the property was added, once something on the receiving end unexpectedly gets a missing or malformed field.

public class UploadRequest
{
    public Stream File { get; set; }
}

The rule checks properties and public fields of classes and records whose own name ends with Dto, Request, Response or Contract. It does not trace whether a type is actually reachable from a controller action or a message declaration - it goes by name alone, so a contract named differently is not checked.

Public fields are included because the two serializers disagree about them: Newtonsoft.Json serializes public fields, while System.Text.Json ignores fields unless configured otherwise. A non-serializable field therefore either behaves like the property case or silently disappears depending on which serializer the endpoint happens to use - neither is a contract worth shipping. static and const fields are skipped, since they are not part of the serialized instance.

How to fix it

Remove the property from the contract. If the underlying data is genuinely needed on the other side, expose it as a value (for example the file's bytes, or a completion flag) instead of the runtime object that produced it.

Code examples

Noncompliant code example

public class UploadRequest
{
    public Stream File { get; set; } // Noncompliant {{'File' has type 'System.IO.Stream', which does not serialize to JSON meaningfully - remove it from this contract.}}
}

Compliant solution

public class UploadRequest
{
    public byte[] FileContent { get; set; }
    public string FileName { get; set; }
}
