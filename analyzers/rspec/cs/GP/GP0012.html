Route segments should use kebab-case (lowercase words separated by hyphens), e.g. job-offers instead of jobOffers, JobOffers or job_offers.

Why is this an issue?

URLs are conventionally treated as case-sensitive. When some endpoints use PascalCase, others camelCase and others snake_case, the casing style becomes one more thing a client has to memorize per endpoint instead of relying on a single, predictable pattern across the whole API. Kebab-case is the most common convention for REST resource paths precisely because it avoids this ambiguity.

[HttpGet("JobOffers")]
public void GetAll() { }

How to fix it

Rewrite the segment in kebab-case.

Code examples

Noncompliant code example

public class JobOffersController
{
    [HttpGet("JobOffers")] // Noncompliant {{Rename route segment 'JobOffers' to kebab-case.}}
    public void GetAll() { }
}

Compliant solution

public class JobOffersController
{
    [HttpGet("job-offers")]
    public void GetAll() { }
}
