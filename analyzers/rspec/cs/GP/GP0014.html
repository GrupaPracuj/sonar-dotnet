Route templates should not end with a trailing slash, e.g. use /users instead of /users/.

Why is this an issue?

Many clients and frameworks treat a path with a trailing slash as distinct from the same path without one. If some routes in a service end with "/" and others don't, callers have to remember which is which per endpoint instead of relying on one consistent shape - a frequent source of subtle 404s and duplicated-route confusion.

[Route("api/users/")]
public void GetAll() { }

Exceptions

The root route, a template that is exactly "/", is not flagged - only a longer template ending in a trailing slash is.

How to fix it

Remove the trailing slash from the route template.

Code examples

Noncompliant code example

public class UsersController
{
    [Route("api/users/")] // Noncompliant {{Remove the trailing slash from the route.}}
    public void GetAll() { }
}

Compliant solution

public class UsersController
{
    [Route("api/users")]
    public void GetAll() { }
}
