A controller that serves REST should derive from ControllerBase or carry [ApiController], not derive from Controller.

Why is this an issue?

Controller is the base for controllers that render views: it adds view lookup, view data, temp data and the partial-view machinery on top of ControllerBase. A controller that only produces JSON inherits all of it and uses none of it.

The cost is not only the unused inheritance. Marking the type [ApiController] turns on the conventions an HTTP API is expected to follow: an invalid model returns 400 with ValidationProblemDetails before the action body runs, complex parameters are inferred as the request body without [FromBody], and attribute routing becomes mandatory rather than optional. Without it, an invalid request reaches the action and each action has to check ModelState for itself - and the ones that forget silently work on a half-bound request.

The declaration also decides which analyses see the type at all. Rules that reason about an HTTP API - the OpenAPI metadata, the response contracts, the authorization responses - skip anything that renders views, because there a returned type is that application's own view model rather than a published contract. A REST controller declared as a view-rendering one is therefore excluded from the checks that were written for it.

The rule reports a controller deriving from Controller, without [ApiController], whose actions declare a produced media type or a response body type, and which never renders a view.

An abstract base controller is not reported: what it is depends on the types deriving from it, and those are reported on their own.

How to fix it

Derive from ControllerBase and mark the type [ApiController]. If some actions do render views, keep those in a separate controller.

Code examples

Noncompliant code example

[Route("files")]
public class FilesController : Controller // Noncompliant
{
    [HttpGet]
    [ProducesResponseType(typeof(UserFiles), StatusCodes.Status200OK)]
    public IActionResult Get() => Ok(new UserFiles());
}

Compliant solution

[ApiController]
[Route("files")]
public class FilesController : ControllerBase
{
    [HttpGet]
    [ProducesResponseType(typeof(UserFiles), StatusCodes.Status200OK)]
    public IActionResult Get() => Ok(new UserFiles());
}
