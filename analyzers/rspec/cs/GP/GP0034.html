A message should be published or sent through Juno's IPublisher or IMessageSender, not through MassTransit's IPublishEndpoint/ISendEndpointProvider/IBus or a raw RabbitMQ connection.

Why is this an issue?

Juno wraps MassTransit rather than hiding it, and the wrapper is where the conventions live: the message-type naming and schema headers, the encryption support, the correlation context carried from the incoming request, and the publish metrics. Publishing straight through MassTransit delivers the message, so nothing fails loudly - the envelope simply lacks whatever the consumers on the other side expect to find, and the publish is missing from the service's outgoing-message telemetry.

public class OrderService
{
    private readonly IPublishEndpoint _publishEndpoint;

    public Task Save(OrderAccepted @event) =>
        _publishEndpoint.Publish(@event);
}

Exceptions

Consuming is not wrapped and is not reported: implementing MassTransit's IConsumer<T> is the sanctioned way to handle a message, and Juno's own examples do exactly that. Bus configuration during start-up is not reported either - that is where MassTransit is supposed to be referenced.

How to fix it

Inject GP.Juno.Abstractions.EventStream.IPublisher to publish an event, or GP.Juno.Abstractions.Massaging.IMessageSender when you need to send to a specific endpoint or attach headers and metadata.

Code examples

Noncompliant code example

public class OrderService
{
    private readonly IPublishEndpoint _publishEndpoint;

    public Task Save(OrderAccepted @event) =>
        _publishEndpoint.Publish(@event); // Noncompliant {{Publish through Juno (IPublisher / IMessageSender) instead of MassTransit's 'Publish'.}}
}

Compliant solution

public class OrderService
{
    private readonly IPublisher _publisher;

    public OrderService(IPublisher publisher) =>
        _publisher = publisher;

    public Task Save(OrderAccepted @event, CancellationToken cancellationToken) =>
        _publisher.Publish(@event, cancellationToken);
}
