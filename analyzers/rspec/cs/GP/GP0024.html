A DELETE endpoint should return 204 No Content, not 200 OK with a response body.

Why is this an issue?

The Microsoft REST API Guidelines state it directly:

DO return a 204-No Content without a resource/body for a DELETE operation (even if the URL identifies a resource that does not exist; do not return 404-Not Found).

Once a resource has been deleted, there is nothing left to represent - returning it in the body adds a payload the client has no real use for, and makes the endpoint's contract inconsistent with every other DELETE endpoint in the API that already returns an empty 204.

HTTP itself does not forbid a body on a DELETE response: MDN documents 200 as valid too, specifically "if the response includes an entity describing the status" - a genuine status/report object, not simply the resource that was just deleted. This rule follows the stricter, more specific Microsoft REST API Guidelines convention of always using 204, which keeps every DELETE endpoint in the API consistent rather than deciding case by case.

For Minimal APIs, the rule covers only inline handlers registered with the official ASP.NET Core MapDelete extension. It reports the official Results/TypedResults factories that unambiguously produce a 200 response body: Ok(value), Json(...), Text(...), and Content(...). A factory with an explicit non-200 or non-constant status code is not reported. Named handlers, nested lambdas, local functions and lookalike mapping or result APIs are outside this scope. For MVC actions, Ok(value) is resolved to a real response factory - Microsoft.AspNetCore.Mvc.ControllerBase/Controller, or Results/TypedResults, since an action may return an IResult too - so a same-named helper declared elsewhere is not reported.

[HttpDelete]
public IActionResult DeleteOrder(int id)
{
    var deleted = _repository.Delete(id);
    return Ok(deleted);
}

How to fix it

Return NoContent() instead of Ok(...) once the deletion has completed.

Code examples

Noncompliant code example

[HttpDelete]
public IActionResult DeleteOrder(int id)
{
    var deleted = _repository.Delete(id);
    return Ok(deleted); // Noncompliant {{DELETE endpoints should return 204 (NoContent) instead of 200 with a response body.}}
}

Compliant solution

[HttpDelete]
public IActionResult DeleteOrder(int id)
{
    _repository.Delete(id);
    return NoContent();
}
