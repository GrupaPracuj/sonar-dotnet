A type published, sent or consumed as a message must be public.

Why is this an issue?

A message contract is read by a different assembly than the one that declares it - that is the whole point. An internal or private contract cannot be referenced by the consuming service at all, so the agreement only holds as long as producer and consumer happen to be the same assembly. The first time the consumer moves out, the contract has to be made public anyway, and by then other code depends on its name and namespace.

A type parameter used by a generic consumer base is not itself a declared message contract and is not reported. The rule checks the concrete contract type when the generic consumer is closed over one.

The usual workaround makes it worse. Since the consumer cannot reference the type, someone redeclares it on the other side - and the transport matches messages by the full type name including the namespace, so the copy has to sit in an identically named namespace or the message is not consumed at all. What was one agreement becomes two declarations kept in step by hand, and the day they drift apart nothing fails to compile.

internal sealed record OrderAccepted(Guid OrderId);

await _publisher.Publish(new OrderAccepted(id));

How to fix it

Make the contract public, and move it to the assembly the consumers reference.

Code examples

Noncompliant code example

internal sealed record OrderAccepted(Guid OrderId);

await _publisher.Publish(new OrderAccepted(id)); // Noncompliant {{'OrderAccepted' is not public, so no other service can reference this contract.}}

Compliant solution

public sealed record OrderAccepted(Guid OrderId);

await _publisher.Publish(new OrderAccepted(id));
