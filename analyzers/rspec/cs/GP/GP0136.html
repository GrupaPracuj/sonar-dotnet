Whole HTTP request, authentication and identity objects should not be passed to a logger.

Why is this an issue?

These objects are containers rather than individual diagnostic values. Depending on the request and authentication scheme, they may expose authorization headers, cookies, query parameters, claims, authentication tokens, redirect addresses and other data that was never intended for the logging system.

Logging the whole object also makes future changes unsafe. A new header, claim or authentication property can begin appearing in logs without any change or review at the logging call site.

logger.LogInformation("Request {Request}", context.Request);

The rule checks values whose semantic type is an ASP.NET Core HttpContext, HttpRequest, HttpResponse, header, cookie, query or form collection, QueryString, ClaimsPrincipal, ClaimsIdentity, AuthenticationProperties or AuthenticationTicket. It also follows direct string interpolation and concatenation. Logging an explicitly selected scalar field is not reported.

How to fix it

Log only the fields required for diagnosis, such as the HTTP method, route name, a non-sensitive business identifier or an approved correlation identifier. Never log authorization headers, cookies or complete claim sets.

Code examples

Noncompliant code example

logger.LogInformation("Request {Request}", context.Request); // Noncompliant

Compliant solution

logger.LogInformation(
    "Method {Method}, correlation {CorrelationId}",
    context.Request.Method,
    context.Request.Headers["X-Correlation-Id"]);
