A CORS policy that allows credentials should accept only explicitly trusted origins.

Why is this an issue?

SetIsOriginAllowed(_ => true) accepts every requesting origin. Combining it with AllowCredentials() lets an untrusted website send authenticated cross-origin requests with the victim's cookies or HTTP authentication and read the response.

The standard AllowAnyOrigin() API makes this unsafe combination visible and ASP.NET Core rejects it. An always-true custom predicate bypasses that safeguard while creating the same effective policy.

How to fix it

Configure the policy with WithOrigins(...) and load a bounded allowlist of trusted origins from configuration. If credentials are not required, remove AllowCredentials().

Code examples

Noncompliant code example

policy.SetIsOriginAllowed(_ => true) // Noncompliant {{Restrict credentialed CORS requests to explicit trusted origins.}}
      .AllowCredentials();

Compliant solution

policy.WithOrigins("https://trusted.example")
      .AllowCredentials();

Exceptions

The rule reports only a single fluent chain containing both AllowCredentials() and a SetIsOriginAllowed(...) predicate that Roslyn proves always returns true. Separate statements are not correlated because they may execute on different control-flow paths. Dynamic predicates and lookalike APIs are not inferred.
