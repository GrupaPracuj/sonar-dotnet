A ChatClientAgent should be created with a stable, deterministic name.

Why is this an issue?

An agent's name is frequently used as a key for scoped state - conversation threads, caches, telemetry dimensions - across process restarts. A name that is missing, null, or generated fresh on every run (a new Guid, a timestamp) silently starts a new identity every time the process starts, orphaning whatever was keyed to the previous run's name.

var agent = new ChatClientAgent(chatClient, name: Guid.NewGuid().ToString());

The rule checks construction of ChatClientAgent from Microsoft.Agents.AI and Microsoft.Extensions.AI. It reports a missing or null name, and names built from Guid.NewGuid(), DateTime.Now, DateTime.UtcNow or DateTime.Today.

Exceptions

A name supplied through an ordinary variable, parameter, or method call is not reported when its stability cannot be determined at the construction site. Literal strings, constants, and static readonly fields with deterministic initializers are stable.

How to fix it

Give the agent a literal or otherwise deterministic name, for example one sourced from configuration through an ordinary parameter or field.

Code examples

Noncompliant code example

var agent = new ChatClientAgent(chatClient, name: Guid.NewGuid().ToString()); // Noncompliant {{Give this ChatClientAgent a stable, deterministic name instead of an unstable or missing one.}}

Compliant solution

var agent = new ChatClientAgent(chatClient, name: "invoice-summarizer");
