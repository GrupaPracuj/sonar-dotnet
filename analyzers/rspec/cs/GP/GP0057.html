A message contract should not inherit from an entity, an aggregate root or another domain type.

Why is this an issue?

Inheritance puts the base type's members on the wire. The contract looks small and deliberate at its own declaration, while what actually gets serialized is everything the base class exposes - the entity's identity, its audit columns, its navigation properties. Nobody chose that payload, and nobody reviewing the contract can see it.

Microsoft's guidance on integration events warns against the coupling this creates, for the same reason:

What is not recommended is sharing a common integration events library across multiple microservices; doing that would be coupling those microservices with a single event definition data library. You do not want to do that for the same reasons that you do not want to share a common domain model across multiple microservices: microservices must be completely autonomous.

Inheriting a domain type does that implicitly - the contract drags the shared model in without anyone deciding to share it. It also re-creates the coupling that publishing a domain type would create, through a door that is easier to miss. A change to the domain base class changes the published message for every contract that derives from it, in a commit that never touched a contract. And because MassTransit derives publish topology from the type hierarchy, adding or changing a base type can change which consumers receive the message at all.

public class OrderAcceptedContract : Order   // Order is an EF entity
{
    public DateTimeOffset OccurredAt { get; init; }
}

A base type counts as an entity only on deterministic signals: membership of a DbSet<T>, EF mapping attributes, or inheritance from one of the explicitly configured entityBaseTypes. A namespace alone is not treated as evidence.

The derived type is considered a contract only when it is declared in a Contracts or *.Contracts namespace, is an actual ASP.NET controller or Minimal API response payload, or is published, sent, responded with or registered through GP.Juno or MassTransit. Its name and suffix are not evidence.

Exceptions

Inheriting from another contract, or implementing a marker interface, is not reported - only a base class that is a domain type.

How to fix it

Declare the contract independently and copy across the few fields consumers actually need.

Code examples

Noncompliant code example

public class OrderAcceptedContract : Order // Noncompliant {{'Order' is a domain type - a contract that inherits it publishes the whole entity.}}
{
    public DateTimeOffset OccurredAt { get; init; }
}

Compliant solution

public sealed record OrderAcceptedContract(Guid OrderId, decimal Total, string Currency, DateTimeOffset OccurredAt);
