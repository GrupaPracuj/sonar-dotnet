An OpenAPI security scheme reference should use exactly the same identifier, including casing, as its definition.

Why is this an issue?

OpenAPI component identifiers are case-sensitive. Defining Bearer while referencing bearer leaves the security requirement pointing at a different, missing scheme. Swagger UI then cannot apply authentication as configured.

The rule checks only constant identifiers within the same AddSwaggerGen configuration and reports case-only mismatches. Dynamic identifiers and separate configuration scopes are not inferred.

How to fix it

Use one exact identifier for both the security definition and every reference to it.

Code examples

Noncompliant code example

options.AddSecurityDefinition("Bearer", scheme);
new OpenApiSecuritySchemeReference("bearer", document); // Noncompliant

Compliant solution

options.AddSecurityDefinition("bearer", scheme);
new OpenApiSecuritySchemeReference("bearer", document);
