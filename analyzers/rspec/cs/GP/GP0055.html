A message should be published as a declared contract type, not as object, dynamic, an anonymous type or a loose dictionary.

Why is this an issue?

The type is the contract. It is what MassTransit uses to decide the exchange to publish to and therefore which consumers receive the message, and it is what documents the payload for the team on the other side. Publishing an anonymous type or a dictionary removes both: the topology is derived from a type that exists only at that call site, and nothing anywhere states what the message contains.

Consumers then bind to a shape that no compiler checks. Renaming a property, changing its type or dropping it is invisible - the producer compiles, the publish succeeds, and the consumer silently receives a field that is now missing or of the wrong type. That is the same class of failure a contract exists to prevent, reintroduced by the way the message is sent.

await _publisher.Publish(new { OrderId = order.Id, Total = order.Total });
await _publisher.Publish(new Dictionary<string, object> { ["orderId"] = order.Id });

The rule reports publishing or sending object, dynamic, an anonymous type, ExpandoObject, Dictionary<string, object>, JsonElement, JsonDocument or Newtonsoft's JObject.

How to fix it

Declare the contract and publish that.

Code examples

Noncompliant code example

await _publisher.Publish(new { OrderId = order.Id, Total = order.Total }); // Noncompliant {{Publish a declared contract type instead of an anonymous type.}}

Compliant solution

public sealed record OrderAccepted(Guid OrderId, decimal Total, string Currency, DateTimeOffset OccurredAt);

await _publisher.Publish(new OrderAccepted(order.Id, order.Total, order.Currency, DateTimeOffset.UtcNow));
