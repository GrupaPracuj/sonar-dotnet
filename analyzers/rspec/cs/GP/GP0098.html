A type that is not accessible outside its assembly (internal) and has no subtype anywhere in that assembly should be marked sealed.

Why is this an issue?

An internal type can only ever be subclassed by code inside the same assembly (or an assembly explicitly granted access through [InternalsVisibleTo]). When no such subtype actually exists, marking the type sealed costs nothing and lets the JIT use non-virtual dispatch and other sealed-type optimizations. S3260 already reports this for private and file-scoped types, but does not cover internal types, since their potential subtype can be anywhere in the assembly rather than just the containing type or file.

internal class Repository
{
    public void Save() { }
}

How to fix it

Mark the type sealed.

Code examples

Noncompliant code example

internal class Repository // Noncompliant {{'Repository' has no subtype in this assembly and should be sealed.}}
{
    public void Save() { }
}

Compliant solution

internal sealed class Repository
{
    public void Save() { }
}

Exceptions

Not reported: types already sealed, static or abstract; partial types (to avoid reporting once per file for the same type); and every type in an assembly that carries [InternalsVisibleTo], since a friend assembly may then subclass a type that has no subtype locally.
