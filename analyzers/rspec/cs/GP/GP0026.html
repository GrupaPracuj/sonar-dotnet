An endpoint that creates a resource should return 201 Created, not a bare 200 OK.

Why is this an issue?

The Microsoft REST API Guidelines describe a resource-creating operation as returning 201-Created with URL of created resource. MDN is more specific about why the URL matters:

The newly-created items can be returned in the body of the response message, but must be locatable by the URL of the initiating request or by the URL in the value of the Location header provided with the response.

200 OK doesn't carry that expectation - a client reading a 200 has no standard way to know it just created something, or where to find it afterwards. 201, together with a Location header (which CreatedAtAction/ CreatedAtRoute set automatically), makes both facts explicit.

[HttpPost]
public IActionResult CreateOrder(OrderRequest request)
{
    var order = _repository.Create(request);
    return Ok(order);
}

Exceptions

Only [HttpPost] actions whose name starts with a creation verb (Create, Add, Insert, Register) are checked - POST is also routinely used for actions that don't create a resource at all (a login, a search, a calculation), where 200 is the correct response and there is nothing to name after a "creation" verb. Ok is resolved to a real response factory - Microsoft.AspNetCore.Mvc.ControllerBase/Controller, or Results/TypedResults, since an action may return an IResult too - so a same-named helper declared elsewhere is not reported.

Actions explicitly named as a DryRun are also excluded. A Create...DryRun endpoint validates or previews what would happen without actually creating a resource, so there is no created URL to return and 200 OK is the expected outcome.

An Add... action whose POST route is exactly one existing resource parameter, such as [HttpPost("{id:guid}")], is also excluded. That shape represents an action on the addressed resource rather than creating a new member in a collection.

How to fix it

Return CreatedAtAction/CreatedAtRoute (or Created with an explicit URL) instead of Ok.

Code examples

Noncompliant code example

[HttpPost]
public IActionResult CreateOrder(OrderRequest request)
{
    var order = _repository.Create(request);
    return Ok(order); // Noncompliant {{POST action 'CreateOrder' is named for creation - return 201 Created instead of 200 Ok.}}
}

Compliant solution

[HttpPost]
public IActionResult CreateOrder(OrderRequest request)
{
    var order = _repository.Create(request);
    return CreatedAtAction(nameof(GetOrder), new { id = order.Id }, order);
}
