An event contract registered for publishing should describe something that already happened and should not use the technical Event suffix.

Why is this an issue?

An event represents a fact: something that has already occurred in the system (PaymentReceived, OrderShipped). Once the type is published through the messaging infrastructure, its role as an event is already clear from that context, so appending the technical suffix Event to its name (PaymentReceivedEvent) is redundant noise that doesn't add any information for the reader.

This rule only applies when the type is actually used with event semantics: a publish declaration such as Publishes<T>() or a real messaging publish operation such as Publish(...) / PublishAsync(...). Merely sending a type whose name ends with Event does not make it a published event.

public class PaymentReceivedEvent { }

appConfig.Publishes<PaymentReceivedEvent>();

How to fix it

Rename the published event type to a past-tense name that describes what happened, without the technical suffix.

Code examples

Noncompliant code example

public class PaymentReceivedEvent { }

public static class Startup
{
    public static void RegisterMessages(AppConfig appConfig) =>
        appConfig.Publishes<PaymentReceivedEvent>(); // Noncompliant {{Rename event 'PaymentReceivedEvent' to remove the 'Event' suffix.}}
}

Compliant solution

public class PaymentReceived { }

public static class Startup
{
    public static void RegisterMessages(AppConfig appConfig) =>
        appConfig.Publishes<PaymentReceived>();
}
