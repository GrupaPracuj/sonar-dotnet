An action's name should match the HTTP verb it is annotated with: a method annotated with [HttpGet] should not start with a mutating verb like Delete or Create, and a method annotated with [HttpDelete] should not start with a read or creation verb like Get or Create.

Why is this an issue?

When an action's name and its actual HTTP verb disagree - for example [HttpGet] DeleteUser() or [HttpDelete] CreateUser() - it is unclear which one reflects the real behavior. A caller relying on the method name assumes the wrong operation, and a maintainer skimming the controller has to open every method body to be sure what it actually does, defeating the point of a descriptive name.

GET in particular is not a free choice of spelling. It is a safe method, which MDN defines as:

An HTTP method is safe if it doesn't alter the state of the server. In other words, a method is safe if it leads to a read-only operation.

Callers, proxies, browsers and crawlers all rely on that guarantee - a GET may be retried, prefetched or cached. An action named DeleteUser behind [HttpGet] either breaks the guarantee, in which case something will eventually delete a user by following a link, or it is misnamed. Both are worth fixing.

[HttpGet]
public IActionResult DeleteUser()
{
    return Ok();
}

Exceptions

[HttpPost], [HttpPut] and [HttpPatch] are deliberately out of scope: those verbs are used both for CRUD operations and for arbitrary non-CRUD actions (for example a [HttpPost] Login()), so a leading-verb mismatch there isn't a reliable signal.

For [HttpGet], the complete set of forbidden leading words is Create, Update, Delete, Remove, Add, Insert, Save, Modify and Edit. For [HttpDelete], it is Get, Find, Search, List, Fetch, Retrieve, Create, Add and Insert. Only the first Pascal-case word of the method name is checked.

How to fix it

Rename the action so its leading verb matches what it actually does, or use the HTTP verb that matches the existing name.

Code examples

Noncompliant code example

[HttpGet]
public IActionResult DeleteUser() // Noncompliant {{Method 'DeleteUser' looks like it performs a mutating action but is annotated with [HttpGet].}}
{
    return Ok();
}

Compliant solution

[HttpGet]
public IActionResult GetUser()
{
    return Ok();
}
