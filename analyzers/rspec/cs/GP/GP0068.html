An enum a contract puts on the wire should have a zero value meaning "not recognised".

Why is this an issue?

Enums on a contract are the part most likely to grow. A new status, a new reason, a new category - the producer adds a member and deploys, and every consumer that was built before that moment now receives a number it has no name for. What happens next depends entirely on whether the enum has somewhere safe to land.

Microsoft's enum guidance names the risk directly:

There is a potential application compatibility problem when the newly added value is returned from an existing API, because poorly written applications might not handle the new value correctly.

Zero is where an unrecognised or absent value ends up: it is the default for the underlying integer, so a consumer deserializing a member it does not know, or a payload where the field is missing, gets zero either way. If zero has a name that means "unknown", the consumer can detect that case and decide what to do. If zero happens to be a real business value, the same situation silently becomes that value instead - a payment whose status the consumer could not read is quietly treated as Pending.

public enum OrderStatus
{
    Pending,     // = 0, so an unrecognised status becomes "Pending"
    Accepted,
    Shipped,
}

The rule only looks at enums a contract actually exposes, so an internal enum is not reported. The accepted names come from unknownValueNames, which defaults to Unknown,Unspecified,None - Microsoft's guidance suggests None for the zero value generally, while an integration contract is usually clearer with Unknown, since the point is that the value could not be interpreted rather than that nothing was set.

How to fix it

Add a zero member named for the unknown case and shift the real values up. On an enum that is already published, keep the existing numbers and give zero its name only if zero was never a valid value - otherwise renumbering is itself a breaking change.

Code examples

Noncompliant code example

public enum OrderStatus // Noncompliant {{'OrderStatus' is exposed by a contract but has no zero value named Unknown - a consumer cannot represent a value it does not recognise.}}
{
    Pending = 1,
    Accepted = 2,
}

public sealed record OrderAcceptedContract(Guid OrderId, OrderStatus Status);

Compliant solution

public enum OrderStatus
{
    Unknown = 0,
    Pending = 1,
    Accepted = 2,
}

public sealed record OrderAcceptedContract(Guid OrderId, OrderStatus Status);
