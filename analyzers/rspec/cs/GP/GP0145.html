A structured AI response should be deserialized with a JsonSerializerOptions that disallows unmapped members, and into a typed model rather than a dynamic value.

Why is this an issue?

An AI-generated response is untrusted input in every sense that matters for deserialization: the model can hallucinate extra fields, omit expected ones, or - in the presence of a prompt injection - be steered into producing a payload that was never intended to reach application code as data. Deserializing it with the default, permissive member handling silently accepts whatever shape the model produced. Deserializing it into dynamic, ExpandoObject, or a loose JsonDocument is worse still: nothing about the target type constrains what the response is allowed to contain, so validation has to happen by hand, if at all, at every place the value is subsequently used.

var invoice = JsonSerializer.Deserialize<InvoiceData>(response.Text);

The rule recognizes the Text property of Microsoft.Extensions.AI.ChatResponse and AgentRunResponse from Microsoft.Extensions.AI or Microsoft.Agents.AI when it is passed directly to System.Text.Json.JsonSerializer.Deserialize(), DeserializeAsync(), JsonDocument.Parse() or ParseAsync(). It reports deserialization without JsonSerializerOptions, options that are provably missing UnmappedMemberHandling = JsonUnmappedMemberHandling.Disallow, and deserialization into dynamic, ExpandoObject or JsonDocument.

Exceptions

AI response text passed through another variable or method is not reported. A JsonSerializerOptions instance supplied through a parameter, field, or method call is also not reported because its configuration cannot be determined at the deserialization site.

How to fix it

Deserialize into a specific typed model, and pass a JsonSerializerOptions with UnmappedMemberHandling set to JsonUnmappedMemberHandling.Disallow.

Code examples

Noncompliant code example

public InvoiceData Extract(ChatResponse response) =>
    JsonSerializer.Deserialize<InvoiceData>(response.Text); // Noncompliant {{This AI response is deserialized without a JsonSerializerOptions that disallows unmapped members - pass one with UnmappedMemberHandling.Disallow.}}

Compliant solution

public InvoiceData Extract(ChatResponse response) =>
    JsonSerializer.Deserialize<InvoiceData>(response.Text, new JsonSerializerOptions { UnmappedMemberHandling = JsonUnmappedMemberHandling.Disallow });
