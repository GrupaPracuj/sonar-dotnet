Route paths should not repeat an HTTP method name, e.g. use /orders, not /get-orders.

Why is this an issue?

The action is already expressed by the HTTP method (GET, POST, PUT, PATCH, DELETE). Repeating that method name in the path is redundant, and when the verb in the path disagrees with the actual HTTP method - for example [HttpPost("get-order")] - it actively misleads anyone reading the route about what the endpoint does.

[HttpGet("get-orders")]
public void GetAll() { }

Checked verbs

The fixed, case-insensitive list is get, post, put, patch and delete.

Exceptions

A word that merely starts with the same letters as a verb, without a real word boundary (-, _, or an uppercase letter) after it, is not flagged. Workflow and custom-operation segments such as cancel, approve and validate-payment are also allowed because their semantics cannot be expressed by choosing a different HTTP method.

How to fix it

Remove the duplicated HTTP method name from the path and let the HTTP method express it.

Code examples

Noncompliant code example

public class OrdersController
{
    [HttpGet("get-orders")] // Noncompliant {{Remove the verb 'get' from the route; the HTTP method already expresses the action.}}
    public void GetAll() { }
}

Compliant solution

public class OrdersController
{
    [HttpGet("orders")]
    public void GetAll() { }
}
