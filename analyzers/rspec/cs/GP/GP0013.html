Route paths should use nouns to identify resources, e.g. /orders, not a verb describing an action, e.g. /getOrders or /create-order.

Why is this an issue?

In a resource-oriented API, the action is already expressed by the HTTP method (GET, POST, PUT, PATCH, DELETE). Repeating it as a verb in the path is redundant, and when the verb in the path disagrees with the actual HTTP method - for example [HttpPost("get-order")] - it actively misleads anyone reading the route about what the endpoint does.

[HttpGet("get-orders")]
public void GetAll() { }

Exceptions

A word that merely starts with the same letters as a verb, without a real word boundary (-, _, or an uppercase letter) after it, is not flagged: addresses is compliant even though it starts with add, and so are checks, searches and confirmations.

How to fix it

Remove the verb from the path and let the HTTP method express the action; keep the path itself a plural noun for the resource.

Code examples

Noncompliant code example

public class OrdersController
{
    [HttpGet("get-orders")] // Noncompliant {{Remove the verb 'get' from the route; the HTTP method already expresses the action.}}
    public void GetAll() { }
}

Compliant solution

public class OrdersController
{
    [HttpGet("orders")]
    public void GetAll() { }
}
