A namespace should not use the same name as a type declared directly inside it.

Why is this an issue?

When a namespace and a type share the same name, the last segment of the namespace and the type become indistinguishable by name alone. Several compilers - and human readers - then need the type to be fully qualified everywhere, because the short name is ambiguous between "the namespace" and "the type in it". Fabrikam.Debug could be the namespace itself or the Debug class declared inside it, and only a fully qualified reference such as Fabrikam.Debug.Debug resolves the ambiguity.

namespace Fabrikam
{
    namespace Debug
    {
        public class Debug
        {
        }
    }
}

How to fix it

Rename either the namespace or the type so the two no longer collide. Which one to rename is a judgment call the rule does not make for you: it depends on which name better describes the namespace's purpose versus the type's role.

Code examples

Noncompliant code example

namespace Fabrikam.Debug // Noncompliant {{Namespace 'Debug' should not share a name with the type 'Debug' declared inside it.}}
{
    public class Debug
    {
    }
}

Compliant solution

namespace Fabrikam.Diagnostics
{
    public class Debug
    {
    }
}
