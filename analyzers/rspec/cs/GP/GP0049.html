A message contract member that holds personal data should be classified with an approved attribute or interface.

Why is this an issue?

Personal data on a message travels further than personal data in a method. The payload is serialized onto the broker, held in the queue until every subscriber has read it, copied into the error queue when a consumer fails, and read by whoever inspects the broker while diagnosing an incident. Each of those is a place the data now lives, and none of them is obvious from the contract's declaration.

The rule does not object to sending personal data - services legitimately need to. It objects to sending it unmarked. A classification is what lets the rest of the organisation answer questions it will eventually be asked: which contracts carry personal data, which queues therefore need a retention policy, and what has to be reviewed when a subject exercises their rights. Without it, that inventory is reconstructed by reading every contract by hand.

public sealed record CandidateRegistered(Guid CandidateId, string Email, string Pesel);

Members are matched by name, word by word, against a personal-data vocabulary - email, pesel, phone, iban, surname, firstname, lastname, birthdate, dateofbirth, creditcard.

Exceptions

A contract is not reported once it or the member carries one of the types named in the classificationAttributes or classificationInterfaces parameters. Both default to empty, which means that until they are configured the rule reports every unclassified personal-data member - configure them first, then let the rule find what is left.

How to fix it

Mark the contract, or the individual member, with the classification your organisation uses. If the field is not actually needed by any consumer, removing it is better than classifying it.

Code examples

Noncompliant code example

public sealed record CandidateRegisteredContract(Guid CandidateId, string Email); // Noncompliant {{'Email' is personal data - classify it with an approved attribute or interface.}}

Compliant solution

[PersonalData]
public sealed record CandidateRegisteredContract(Guid CandidateId, string Email);
