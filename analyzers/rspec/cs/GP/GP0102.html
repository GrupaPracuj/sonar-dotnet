HTTP actions with an abstract result type should declare the concrete payload returned on success.

Why is this an issue?

IActionResult, ActionResult and IResult describe how ASP.NET writes a response, but not the schema of its body. When an action returns Ok(value), Created(..., value) or Accepted(..., value), OpenAPI needs explicit metadata to generate the correct response schema and strongly typed clients.

The rule also unwraps Task and ValueTask, works without ApiController or Swashbuckle, and examines only response factories actually returned from the action. A concrete declared result such as ActionResult<OrderResponse> already carries the schema and is not reported.

Exceptions

Actions excluded from API Explorer, actions covered by ASP.NET API conventions, and classic MVC controllers serving views are not reported. Successful responses without a body do not need a payload schema.

How to fix it

Add ProducesResponseType (or equivalent concrete response metadata) for the successful response.

Code examples

Noncompliant code example

[HttpGet("{id}")]
public async Task<IActionResult> Get(string id) // Noncompliant {{Declare the concrete successful response type with ProducesResponseType.}}
{
    return Ok(await Load(id));
}

Compliant solution

[HttpGet("{id}")]
[ProducesResponseType(typeof(OrderResponse), StatusCodes.Status200OK)]
public async Task<IActionResult> Get(string id)
{
    return Ok(await Load(id));
}
