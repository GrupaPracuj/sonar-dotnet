Public APIs should expose IDictionary or IDictionary<TKey, TValue> instead of Hashtable or Dictionary<TKey, TValue>.

Why is this an issue?

The concrete types are implementation-oriented data structures. Exposing them couples callers to a specific storage implementation and prevents an API from changing that implementation without breaking its contract.

How to fix it

Use the corresponding dictionary interface in the public member signature and keep the concrete implementation private.

Code examples

Noncompliant code example

public Dictionary<string, Order> Orders { get; } // Noncompliant {{Expose a dictionary interface instead of the concrete 'Dictionary' type in this public property.}}

Compliant solution

public IDictionary<string, Order> Orders { get; }

Exceptions

Overrides cannot change their inherited signature and are not reported. Serialization properties and fields marked with XmlElementAttribute are also excluded.
