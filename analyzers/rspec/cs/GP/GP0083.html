A collection or dictionary initializer should not add the same compile-time constant twice.

Why is this an issue?

A collection initializer such as new Dictionary<string, int> { {"a", 1}, {"a", 2} } desugars into one Add call per element, executed in source order. For a dictionary, the second Add("a", 2) call fails at the moment it runs, because the key is already present - the object never finishes constructing, and the failure is a plain ArgumentException with a message that says nothing about which of possibly many initializers caused it. This is not a style preference: the code is guaranteed to throw the first time that line executes, on every run, regardless of input.

A set-like initializer, e.g. new HashSet<string> { "x", "x" }, does not throw - Add on a type built around uniqueness usually just returns false for the repeat - but the duplicate is still dead code: it does not do anything, and its presence usually means a copy-paste mistake rather than an intentional no-op.

var statusByCode = new Dictionary<int, string>
{
    { 200, "OK" },
    { 404, "Not Found" },
    { 200, "Success" }, // never reached - the dictionary already threw on the line above
};

Exceptions

Only elements whose key (or value, for a plain set-style element) is a compile-time constant are ever compared. A key that is a local variable, a method call, or any other non-constant expression is never flagged, even if it happens to be equal to another element at run time - there is no way to know that without executing the program, so the rule stays silent rather than guessing.

For string-keyed dictionaries, the rule also honors the directly supplied StringComparer.OrdinalIgnoreCase comparer. Other custom or culture-sensitive comparer semantics are not inferred.

How to fix it

Remove the duplicate, or fix the copy-paste mistake that produced two entries with the same key when two different keys were intended.

Code examples

Noncompliant code example

var statusByCode = new Dictionary<int, string>
{
    { 200, "OK" },
    { 404, "Not Found" },
    { 200, "Success" }, // Noncompliant {{Duplicate key '200' in dictionary initializer - the second 'Add' call throws ArgumentException at runtime.}}
};

Compliant solution

var statusByCode = new Dictionary<int, string>
{
    { 200, "OK" },
    { 404, "Not Found" },
};
