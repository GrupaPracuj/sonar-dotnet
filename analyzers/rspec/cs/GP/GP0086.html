A translation-only Microsoft.EntityFrameworkCore.EF.Functions member such as Like must only be called from inside an inline Queryable lambda that Entity Framework Core can translate to SQL.

Why is this an issue?

EF.Functions exposes methods that exist purely to be recognized by EF Core's query translator and turned into SQL constructs - they have no real .NET implementation. Calling one as an ordinary C# method - outside a LINQ expression tree that gets translated - throws System.NotSupportedException immediately and unconditionally. There is no code path where it can succeed; it is not a matter of bad input or an edge case, every single call fails the same way.

var isMatch = EF.Functions.Like(customer.Name, "%acme%"); // throws NotSupportedException every time

This most often happens when a call is copied out of a Where/Select lambda into a helper method, or is written inside a lambda that looks query-like but actually converts to a plain Func<>/Action<> - for instance because it is passed to List<T>.Where (LINQ to Objects) instead of IQueryable<T>.Where (LINQ to Entities), or wrapped in new Func<bool>(...). In both cases nothing marks the call as being inside a query, so EF Core never gets a chance to translate it.

Exceptions

The rule accepts only calls contained in an inline lambda argument to a System.Linq.Queryable operator. A standalone Expression<TDelegate> variable is not enough evidence that EF Core will translate it, and methods merely marked [DbFunction] are outside scope because they can also have valid managed implementations.

How to fix it

Move the call inside a lambda that is actually passed to an IQueryable<T> LINQ operator (Where, Select, OrderBy, ...), so it becomes part of the expression tree EF Core translates to SQL. If the surrounding collection is not an IQueryable<T> - for example it is already an in-memory List<T> - the comparison has to be rewritten using ordinary .NET APIs (such as pattern matching for a LIKE-style check) instead of a database-only function.

Code examples

Noncompliant code example

bool MatchesPattern(string name) =>
    EF.Functions.Like(name, "%acme%"); // Noncompliant {{'Like' is only meaningful inside a query translated by Entity Framework - call it directly inside an inline Queryable lambda.}}

var matches = customers.Where(c => MatchesPattern(c.Name)).ToList(); // MatchesPattern's body runs as ordinary code, not as part of the translated query

Compliant solution

var matches = customers.Where(c => EF.Functions.Like(c.Name, "%acme%")).ToList(); // the lambda converts to Expression<Func<Customer, bool>>
