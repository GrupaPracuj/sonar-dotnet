A message contract should not declare a member whose name says it holds a secret.

Why is this an issue?

A message does not go to one place. It is serialized onto a broker, kept in a queue until every subscriber has read it, copied into the error queue when a consumer fails, written to whatever traces the transport records, and read by anyone who can inspect the broker while diagnosing a problem. A password or token placed in the payload is therefore not shared with one consumer - it is persisted, replicated and made visible to a much wider audience than the two services that were being connected.

Unlike a leaked log line, a leaked contract cannot be rotated away quietly: the field is part of a published interface, so removing it is a breaking change for every consumer that already reads it.

public sealed record ServiceRegistered(string ServiceName, string ApiKey);

Names are matched word by word, so ApiKey, clientSecret, refresh_token and ConnectionString all match. A name that only points at a secret rather than holding one does not: a trailing Id, Reference, Name, Uri, Path, Type, Count or Length makes ApiKeyId, CredentialReference and SecretUri compliant - which matters, because those are exactly the shapes this rule recommends as the fix.

Exceptions

Only types whose own name ends with one of the contract suffixes are examined, the same convention the other contract rules use, so an internal options class that legitimately carries a secret is not reported.

How to fix it

Do not move the secret. Send a reference the consumer can exchange for the secret through a channel that authenticates it - a secret identifier, a key vault path, or a short-lived token requested by the consumer itself.

Code examples

Noncompliant code example

public sealed record ServiceRegisteredContract(string ServiceName, string ApiKey); // Noncompliant {{'ApiKey' looks like a secret - a message contract is persisted on the broker and readable by every subscriber.}}

Compliant solution

public sealed record ServiceRegisteredContract(string ServiceName, string CredentialReference);
