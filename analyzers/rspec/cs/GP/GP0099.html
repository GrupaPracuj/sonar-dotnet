A public or protected property without an equally accessible setter should not return an array.

Why is this an issue?

An array returned by a property is not write-protected, even when the property itself is read-only: the caller receives a reference to the same stored array instance and can mutate its elements directly, bypassing whatever invariants the owning type is meant to enforce. Callers also commonly mistake the property for an indexed collection and re-read it inside a loop, re-evaluating the property (and, in some implementations, re-allocating a defensive copy) on every iteration.

public class Book
{
    public string[] Pages { get; }
}

How to fix it

Change the property to return a read-only collection type such as ReadOnlyCollection<T> or IReadOnlyList<T>, or turn it into a method that returns a defensive copy of the array.

Code examples

Noncompliant code example

public class Book
{
    public string[] Pages { get; } // Noncompliant {{'Pages' returns an array - callers can mutate it through this property. Return a read-only collection, or a method that returns a copy.}}
}

Compliant solution

public class Book
{
    public ReadOnlyCollection<string> Pages { get; }
}

Exceptions

Not reported:

  • a property with a public or protected setter - its mutability is already an explicit part of the API
  • a property on a type deriving from System.Attribute - an attribute argument can only be an array, so there is no other shape to move to
  • a one-dimensional byte[] for a binary payload - collection wrappers do not fit the common file and stream APIs, and copying can be expensive
  • a property on a type recognised as a message or HTTP response contract, including source types under a nested .Contracts.* namespace inside an assembly matching *Contracts - these expose arrays for serialization, with no in-process aliasing risk. An assembly named *.Contract or *.Commands does not count as a contract assembly.
  • an override, whose shape is dictated by the member it overrides
  • a getter proven to build a fresh array on every path - a collection expression, a new array or a LINQ ToArray() - because callers cannot reach stored state through it
