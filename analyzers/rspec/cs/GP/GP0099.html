A public or protected property without an equally accessible setter should not return an array.

Why is this an issue?

An array returned by a property is not write-protected, even when the property itself is read-only: the caller receives a reference to the same stored array instance and can mutate its elements directly, bypassing whatever invariants the owning type is meant to enforce. Callers also commonly mistake the property for an indexed collection and re-read it inside a loop, re-evaluating the property (and, in some implementations, re-allocating a defensive copy) on every iteration.

public class Book
{
    public string[] Pages { get; }
}

How to fix it

Change the property to return a read-only collection type such as ReadOnlyCollection<T> or IReadOnlyList<T>, or turn it into a method that returns a defensive copy of the array.

Code examples

Noncompliant code example

public class Book
{
    public string[] Pages { get; } // Noncompliant {{'Pages' returns an array - callers can mutate it through this property. Return a read-only collection, or a method that returns a copy.}}
}

Compliant solution

public class Book
{
    public ReadOnlyCollection<string> Pages { get; }
}

Exceptions

Not reported: properties with a public or protected setter, because their mutability is already an explicit part of the API; properties on a type deriving from System.Attribute (an attribute argument can only be an array, never a collection, so there is no alternative shape to move to); one-dimensional byte[] properties used for binary payloads, where collection wrappers are not compatible with common file and stream APIs and defensive copying can be prohibitively expensive; properties on a source type semantically recognized as a message or HTTP response contract - including source types declared under nested .Contracts.* namespaces inside an assembly whose name matches *Contracts - these legitimately expose arrays for wire serialization, with no in-process aliasing risk; and override properties, since the property's shape is dictated by the member it overrides. Similarly named assemblies such as *.Contract or *.Commands are not treated as contract assemblies. Properties proven to create a fresh array on every getter path, for example with an expression-bodied collection expression, new array, or LINQ ToArray(), are also not reported because callers cannot mutate stored object state.
