A public or protected property should not return an array.

Why is this an issue?

An array returned by a property is not write-protected, even when the property itself is read-only: the caller receives a reference to the same array instance and can mutate its elements directly, bypassing whatever invariants the owning type is meant to enforce. Callers also commonly mistake the property for an indexed collection and re-read it inside a loop, re-evaluating the property (and, in some implementations, re-allocating a defensive copy) on every iteration.

public class Book
{
    public string[] Pages { get; }
}

How to fix it

Change the property to return a read-only collection type such as ReadOnlyCollection<T> or IReadOnlyList<T>, or turn it into a method that returns a defensive copy of the array.

Code examples

Noncompliant code example

public class Book
{
    public string[] Pages { get; } // Noncompliant {{'Pages' returns an array - callers can mutate it through this property. Return a read-only collection, or a method that returns a copy.}}
}

Compliant solution

public class Book
{
    public ReadOnlyCollection<string> Pages { get; }
}

Exceptions

Not reported: properties on a type deriving from System.Attribute (an attribute argument can only be an array, never a collection, so there is no alternative shape to move to); properties on a type recognized as a message contract (name ending in Dto, Request, Response, Contract, Event, Command or Message) - these legitimately expose arrays for wire serialization, with no in-process aliasing risk; and override properties, since the property's shape is dictated by the member it overrides.
