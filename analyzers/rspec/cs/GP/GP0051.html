A published event should state when the fact it describes occurred.

Why is this an issue?

An event describes something that already happened. When it does not say when, the only time a consumer has is the moment it happened to receive the message - and that is not the same thing. A redelivery after an outage, a queue that backed up, a consumer started later to replay history: all of them make receive time drift arbitrarily far from occurrence time. Any consumer that orders events, computes a duration, or decides whether a newer fact has superseded an older one is then working from the wrong clock.

The failure is quiet, because processing succeeds. A consumer building a timeline simply produces a timeline of when its own queue was drained. Adding the timestamp later does not fix the messages already published, so it has to be there from the start.

public sealed record PaymentReceived(Guid PaymentId, decimal Amount, string Currency);

appConfig.Publishes<PaymentReceived>();

The rule looks at the types actually registered for publishing or passed to a publish call, so a contract that is never published is not reported. It requires a DateTimeOffset member named OccurredAt or OccurredAtUtc. Names such as OccurredOn and Timestamp are not accepted. DateTimeOffset rather than DateTime is deliberate and matches S6566: an instant crossing a service boundary needs its offset.

The issue is reported once on the event type declaration, regardless of how many registrations or publish calls use that type. When the event is declared in a referenced assembly whose source is not part of the current analysis, one issue is reported on the first publish use instead because the declaration is not available to the analyzer.

Exceptions

Only publishing is checked, not sending. A command says what should happen next, so it has no occurrence time to state.

How to fix it

Add the occurrence time to the contract and set it where the fact is recorded - not where the message is published, which may be later.

Code examples

Noncompliant code example

public sealed record PaymentReceived(Guid PaymentId, decimal Amount, string Currency); // Noncompliant {{'PaymentReceived' is published as an event but does not state when it occurred - add a DateTimeOffset OccurredAt.}}

appConfig.Publishes<PaymentReceived>();
await publisher.Publish(new PaymentReceived(paymentId, amount, currency));
await publisher.Publish(new PaymentReceived(paymentId, amount, currency)); // No duplicate issue

Compliant solution

public sealed record PaymentReceived(Guid PaymentId, decimal Amount, string Currency, DateTimeOffset OccurredAt);

appConfig.Publishes<PaymentReceived>();
