A GET endpoint that returns a collection should respond with 200 OK and an empty collection instead of 204 No Content when there are no items to return.

Why is this an issue?

204 No Content tells the client "there is no body to read", which forces every caller of a collection endpoint to special-case that status instead of simply deserializing the response body and checking whether the array is empty. A collection query that legitimately matches zero rows is still a successful read - the response contract should stay the same (200 with a JSON array) whether that array has items or not.

The rule covers MVC controller actions and inline Minimal API MapGet handlers declared through the official ASP.NET Core mapping extensions. For Minimal APIs, it reports Results.NoContent(), TypedResults.NoContent(), and Results.StatusCode(204) only when the same inline handler also returns a collection through Results.Ok(...) or TypedResults.Ok(...). Parent-resource route parameters do not suppress the issue. Named method handlers are not followed, and nested lambdas or local functions are outside the handler analysis boundary.

[HttpGet]
public IActionResult GetUsers() =>
    NoContent();

Exceptions

The response factory is resolved semantically: NoContent()/StatusCode(204) must come from Microsoft.AspNetCore.Mvc.ControllerBase/Controller, or from the Minimal API Results/TypedResults. A same-named helper declared elsewhere - including on the controller itself - is not reported.

How to fix it

Return Ok(...) with an empty collection instead of NoContent().

The automatic fix is available for MVC actions only. Minimal API result unions require a collection-specific replacement, so no fix is offered for Results or TypedResults.

Code examples

Noncompliant code example

[HttpGet]
public IActionResult GetUsers(bool empty)
{
    if (empty)
    {
        return NoContent(); // Noncompliant {{GET endpoints returning collections should return 200 with an empty collection instead of 204.}}
    }

    return Ok(new List<string>());
}

Compliant solution

[HttpGet]
public IActionResult GetUsers(bool empty)
{
    if (empty)
    {
        return Ok(new List<string>());
    }

    return Ok(new List<string>());
}
