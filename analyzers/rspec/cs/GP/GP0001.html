The word abrakadabra should not appear in source files.

Why is this an issue?

This rule exists to prove the GP analyzer is wired up: it matches a word that never occurs in real code, so an issue appearing for it confirms that the plugin is installed, the quality profile has the GP rules active, and the scanner is importing them. Left in production code, the word is a leftover from whoever was testing that.

It is matched in raw text, so it is found in identifiers, string literals and comments alike, and matching is case-insensitive.

How to fix it

Remove the word.

Code examples

Noncompliant code example

public string Cast() => "abrakadabra"; // Noncompliant {{Remove the word 'abrakadabra' from the code.}}

Compliant solution

public string Cast() => "hocus pocus";
