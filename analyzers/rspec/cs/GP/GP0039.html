Configuration should be bound to a typed configuration class, not read value by value through a string key.

Why is this an issue?

A key read inline is invisible to everything except the line that reads it. Nothing lists what the service needs in order to start, nothing validates it, and a missing or misspelled key does not fail at start-up - it produces null or a default at whatever moment that code path first runs, often in production and often far from the cause. Types are lost too: everything is a string until somebody parses it by hand.

Binding a section to a class turns configuration into part of the service's declared shape: the properties document what is required, the types are checked, the values can be validated once at start-up, and the class is what gets injected instead of a configuration bag threaded through the code. This is what Juno's own examples do - they register configuration with configuration.GetSection("sample").Get<SampleConfig>() and inject the resulting object.

public class OrderService
{
    private readonly IConfiguration _configuration;

    public Task Send() =>
        _client.PostAsync(_configuration["Orders:BaseUrl"], content);
}

Note that IConfiguration itself is not the problem and is not reported - it is how binding is done. Only reading a value out of it by key is.

Exceptions

A direct read inside a method that registers an IServiceCollection is not reported. Such a composition-root method is responsible for turning configuration into concrete framework dependencies; reading one value there, for example an EF Core connection string, does not expose IConfiguration to runtime application services.

How to fix it

Declare a configuration class for the section, bind it once during registration, and inject the class.

Code examples

Noncompliant code example

public class OrderService
{
    private readonly IConfiguration _configuration;

    public Task Send(HttpContent content) =>
        _client.PostAsync(_configuration["Orders:BaseUrl"], content); // Noncompliant {{Bind configuration to a typed class instead of reading it by key.}}
}

Compliant solution

public class OrdersConfig
{
    public string BaseUrl { get; set; }
}

// registration
services.AddSingleton(sp => sp.GetRequiredService<IConfiguration>().GetSection("orders").Get<OrdersConfig>());

public class OrderService
{
    private readonly OrdersConfig _config;

    public OrderService(OrdersConfig config) =>
        _config = config;

    public Task Send(HttpContent content) =>
        _client.PostAsync(_config.BaseUrl, content);
}
