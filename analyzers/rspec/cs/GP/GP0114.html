A 202 Accepted response should tell the client how to track the asynchronous operation.

Why is this an issue?

Status 202 means that processing has been accepted but has not completed. Without a status URI in the Location header or a response body containing tracking information such as an operation identifier, the client cannot determine the eventual outcome.

The rule reports only framework response factories that provably create status 202 with neither a URI nor a body. It does not infer whether the operation actually completed, and it accepts any non-null payload because the payload may contain tracking information.

How to fix it

Return an accepted response with a status URI, or include a payload containing an operation identifier or other tracking information. MVC applications can also use AcceptedAtAction or AcceptedAtRoute.

Code examples

Noncompliant code example

return Accepted(); // Noncompliant

Compliant solution

return AcceptedAtAction(nameof(GetStatus), new { id = operation.Id }, new { operation.Id });
