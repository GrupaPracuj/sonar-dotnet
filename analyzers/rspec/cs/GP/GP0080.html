Raising an event should not pass null as the sender or as the event data.

Why is this an issue?

Event handler signatures reserve two parameters - the sender and the event data - and subscribers are entitled to assume both are usable without a null check. The .NET Framework Design Guidelines are explicit about both:

  • Do not pass null as the sender when raising a nonstatic event - subscribers rely on the sender to know which instance raised the event, especially when the same handler is attached to several instances.
  • Do not pass null as the event data parameter - pass EventArgs.Empty when there is no data to carry, so subscribers can dereference the argument without a null check.
public class Order
{
    public event EventHandler Shipped;

    public void Ship()
    {
        Shipped?.Invoke(null, null); // subscribers cannot tell who raised this, and cannot use the event data without checking for null first
    }
}

The rule reports both the direct invocation syntax legal only inside the type that declares the event (MyEvent(sender, args)) and the explicit form (MyEvent.Invoke(...) / MyEvent?.Invoke(...)), since both raise the event the same way.

Exceptions

Passing null as the sender of a static event is not reported - there is no single instance to point to, and the guideline's advice for that case is more contested, so it is left out of scope here.

How to fix it

Pass this (or whichever instance is actually raising the event) as the sender, and EventArgs.Empty instead of null when there is no event data to carry.

Code examples

Noncompliant code example

public class Order
{
    public event EventHandler Shipped;

    public void Ship()
    {
        Shipped?.Invoke(null, null); // Noncompliant {{Do not pass null as the sender - use 'this' (or the actual raising instance) so subscribers know who raised 'Shipped'.}}
                                      // Noncompliant@-1 {{Do not pass null as the event data for 'Shipped' - pass EventArgs.Empty instead, callers expect a non-null value.}}
    }
}

Compliant solution

public class Order
{
    public event EventHandler Shipped;

    public void Ship()
    {
        Shipped?.Invoke(this, EventArgs.Empty);
    }
}
