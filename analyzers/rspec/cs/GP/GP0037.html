Email should be sent through Juno's email sender, not with System.Net.Mail.SmtpClient.

Why is this an issue?

Juno provides an email-sending abstraction with the templating, request tracking and configured relay that GP services rely on. Reaching for SmtpClient means a second, undocumented delivery path: a hard-coded relay host, no template handling, and nothing recorded about what was sent.

Independently of the GP convention, Microsoft advises against the type for new code:

We don't recommend that you use the SmtpClient class for new development because SmtpClient doesn't support many modern protocols.

The API reference summary is equally blunt - "The SmtpClient type is not recommended for new development" - and Microsoft's platform-compatibility note DE0005 records the same deprecation.

using var client = new SmtpClient("smtp.internal");
client.Send(new MailMessage("noreply@gp.pl", user.Email, subject, body));

How to fix it

Send the message through Juno's email sender, describing it with the email/template info types rather than assembling an SMTP conversation yourself.

Code examples

Noncompliant code example

public void NotifyUser(User user, string subject, string body)
{
    using var client = new SmtpClient("smtp.internal"); // Noncompliant {{Send email through Juno's email sender instead of 'SmtpClient'.}}
    client.Send(new MailMessage("noreply@gp.pl", user.Email, subject, body));
}

Compliant solution

public Task NotifyUser(User user, string templateName, CancellationToken cancellationToken) =>
    _emailSender.Send(new TemplateBasedEmailInfo(user.Email, templateName), cancellationToken);
