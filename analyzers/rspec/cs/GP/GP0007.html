Shared dictionaries should be consumed through Juno.Dictionaries instead of calling the Skidblandir API directly over HTTP.

Why is this an issue?

Juno.Dictionaries is the standard integration layer for shared dictionary data: it centralizes caching, retries and error handling for Skidblandir lookups. Calling the Skidblandir endpoints directly with an HttpClient bypasses all of that, couples the calling code to transport details (URLs, response shapes) that Juno.Dictionaries is meant to hide, and duplicates behavior that the shared layer already provides consistently across services.

public Task<string> Fetch() =>
    _httpClient.GetStringAsync("https://skidblandir.pracuj.local/api/dictionaries/categories");

How to fix it

Replace the direct HTTP call with the corresponding Juno.Dictionaries facade method.

Code examples

Noncompliant code example

public Task<string> Fetch() =>
    _httpClient.GetStringAsync("https://skidblandir.pracuj.local/api/dictionaries/categories"); // Noncompliant {{Use Juno.Dictionaries instead of calling Skidblandir API directly.}}

Compliant solution

public Task<IReadOnlyCollection<string>> Fetch() =>
    _dictionaries.GetItems<string>("categories", new Parameters(), CancellationToken.None);
