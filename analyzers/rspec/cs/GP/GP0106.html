A message registered with Juno as a command should be sent, while a message registered as an event should be published.

Why is this an issue?

Sends<T> declares point-to-point command semantics. Publishing that type broadcasts it as an event and may deliver it to multiple consumers. Conversely, Publishes<T> declares event semantics, which are lost when the message is sent to one endpoint.

The rule reports only when the same compilation contains an explicit, contradictory Juno registration. It does not guess when registration is external or unavailable. If a contract deliberately supports both semantics, register it explicitly with both Sends<T> and Publishes<T>.

How to fix it

Dispatch commands with Send and events with Publish, or correct the registration if it declares the wrong intent.

Code examples

Noncompliant code example

config.Sends<RebuildIndex>();
await publisher.Publish(new RebuildIndex()); // Noncompliant

Compliant solution

config.Sends<RebuildIndex>();
await sender.Send(new RebuildIndex());
