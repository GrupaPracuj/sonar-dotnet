Recurring or delayed work should be scheduled through Juno's ISchedulerFactory/IScheduleJobsRegistry, not with a Timer or a third-party scheduler.

Why is this an issue?

A service runs as several instances. A Timer fires in every one of them, so work meant to happen once per interval happens once per instance - and the more you scale out, the more duplicates you get. Juno's scheduler exists to answer that: the schedule is coordinated rather than per-process, the job is registered where it can be inspected, and failures surface through the usual monitoring instead of being swallowed on a background thread.

A Timer also has no relationship with the host lifetime, so a callback can still be running while the application is shutting down, and an exception thrown inside it takes down the process rather than being reported as a failed job.

public class ReportSender
{
    private readonly Timer _timer;

    public ReportSender() =>
        _timer = new Timer(_ => SendReports(), null, TimeSpan.Zero, TimeSpan.FromHours(1));
}

Exceptions

A Task.Delay inside a loop is not reported. It is used for far too many legitimate things - polling with backoff, a retry pause, a test helper - for the shape alone to mean "this is a scheduled job".

A timer is reported only when its construction demonstrates that it will repeat: a System.Threading.Timer has a known positive period, or a System.Timers.Timer has a known positive interval and is not explicitly configured with AutoReset = false. One-shot timers and timers whose period cannot be established from the construction are not reported.

How to fix it

Register the job through IScheduleJobsRegistry, describing it with a RecurringSchedule, and let Juno decide when and where it runs.

Code examples

Noncompliant code example

public class ReportSender
{
    private readonly Timer _timer;

    public ReportSender() =>
        _timer = new Timer(_ => SendReports(), null, TimeSpan.Zero, TimeSpan.FromHours(1)); // Noncompliant {{Schedule this work through Juno (ISchedulerFactory / IScheduleJobsRegistry) instead of 'Timer'.}}
}

Compliant solution

public class ReportSenderJobs : IScheduleJobsRegistry
{
    public Task ScheduleJobs(ISchedulerFactory schedulerFactory, CancellationToken cancellation) =>
        schedulerFactory
            .CreateAsync("reports")
            .Schedule(new RecurringSchedule(TimeSpan.FromHours(1)), SendReports, cancellation);
}
