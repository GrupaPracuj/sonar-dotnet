Dapper type handlers should be registered once during application startup, not whenever a service or repository instance is constructed.

Why is this an issue?

SqlMapper.AddTypeHandler changes process-wide Dapper configuration. Calling it from an instance constructor repeats a global side effect according to the object's lifetime, hides application configuration inside a repository, and can make tests and concurrent startup order-dependent.

How to fix it

Move type-handler registration to the application's composition root or another one-time static bootstrap step.

Code examples

Noncompliant code example

public OrderRepository()
{
    SqlMapper.AddTypeHandler(new MoneyTypeHandler()); // Noncompliant
}

Compliant solution

public static void ConfigureDapper()
{
    SqlMapper.AddTypeHandler(new MoneyTypeHandler());
}
