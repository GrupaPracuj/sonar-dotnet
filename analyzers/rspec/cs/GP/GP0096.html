A synchronous request-response API path should not make an HTTP call once for every element of a loop.

Why is this an issue?

Every call through HttpClient (or an HttpMessageInvoker) pays for a full network round-trip: DNS resolution, a TCP/TLS handshake or connection reuse, and the latency of the remote server itself - typically tens of milliseconds at best. Making that call once per loop iteration turns an operation that could be a single request into N sequential round-trips, so the total latency scales linearly with the size of whatever collection the loop is iterating over. A page or batch job that looks instant in a test with three items can become unacceptably slow - or trip a rate limit - once it runs against real data.

async Task<List<Order>> GetOrders(HttpClient client, IEnumerable<int> orderIds)
{
    var orders = new List<Order>();
    foreach (var id in orderIds)
    {
        var response = await client.GetAsync($"/orders/{id}"); // one round-trip per order
        orders.Add(await response.Content.ReadFromJsonAsync<Order>());
    }
    return orders;
}

How to fix it

Replace the per-item calls with a single request that accepts multiple identifiers, if the remote API offers a batch or "get many" endpoint. When no such endpoint exists, issue the requests concurrently with Task.WhenAll instead of sequentially - this does not reduce the number of round-trips, but it lets them overlap instead of stacking their latency.

Code examples

Noncompliant code example

async Task<List<Order>> GetOrders(HttpClient client, IEnumerable<int> orderIds)
{
    var orders = new List<Order>();
    foreach (var id in orderIds)
    {
        var response = await client.GetAsync($"/orders/{id}"); // Noncompliant {{This HTTP call directly depends on the loop variable and runs once per iteration - batch the requests or move the call outside the loop.}}
        orders.Add(await response.Content.ReadFromJsonAsync<Order>());
    }
    return orders;
}

Compliant solution

async Task<List<Order>> GetOrders(HttpClient client, IEnumerable<int> orderIds)
{
    var response = await client.PostAsJsonAsync("/orders/batch", orderIds);
    return await response.Content.ReadFromJsonAsync<List<Order>>();
}

Exceptions

The rule follows calls within one compilation from MVC actions and inline Minimal API handlers. Calls that are not reachable from such an endpoint are not reported. Calls through another project are deliberately not guessed.

Only a direct call whose receiver or arguments reference a variable declared by the enclosing loop is reported. This is a deliberately narrow signal that the request changes for each element. Retry and polling loops that repeat the same request are not reported.

A call made from a nested lambda, local function, or LINQ query clause is not attributed to the outer loop. Indirect dependencies through a temporary variable are also not followed; these limitations favor fewer false positives over complete detection.
