An HTTP client registered in an application using Juno HttpApiClient should have an explicit name.

Why is this an issue?

Juno HttpApiClient applies its configuration and policies to named or typed clients. Registering the default client with AddHttpClient() leaves Juno without a client identity and causes application startup to fail.

How to fix it

Register a named client with AddHttpClient("service-name"), or use a typed client.

Code examples

Noncompliant code example

services.AddHttpClient(); // Noncompliant {{Give this HTTP client an explicit name; Juno does not support the default client registration.}}

Compliant solution

services.AddHttpClient("orders");

Exceptions

The rule is enabled only when Juno HttpApiClient is referenced. Standard .NET applications that do not use Juno may legitimately register the default client.
