Missing a required claim should never cause access to be granted.

Why is this an issue?

HasClaim(...) and its GP.Juno equivalents answer whether the caller has a claim. Returning a successful response when that check is false reverses the intended authorization condition and can allow an unauthorized caller to access the operation.

if (!user.HasClaim("filestore_access"))
{
    return Ok();
}

How to fix it

Deny access when the required claim is absent, or grant access only from the branch where the claim is present.

Code examples

Noncompliant code example

public IActionResult DeleteFile(User user)
{
    if (!user.HasClaim("filestore_access")) // Noncompliant
    {
        return Ok();
    }

    return Forbid();
}

Compliant solution

public IActionResult DeleteFile(User user)
{
    if (!user.HasClaim("filestore_access"))
    {
        return Forbid();
    }

    return Ok();
}

Exceptions

The rule only reports direct, unambiguous branch decisions: returning an ASP.NET Core MVC 2xx response or a Minimal API Results/TypedResults 2xx response from the branch where the claim is absent. Boolean-returning helper methods, negating a claim check for another purpose, and correctly returning Forbid when a claim is absent are not reported. Generic HasClaim checks are recognized only on System.Security.Claims.ClaimsPrincipal (or a derived type); unrelated domain methods that happen to have the same name are ignored.
