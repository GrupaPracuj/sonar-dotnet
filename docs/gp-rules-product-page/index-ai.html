Od eksperymentu do produktu

Kontrola tam, gdzie zwykłe reguły C# już nie wystarczają.

Integracja z LLM-em wprowadza nowe powierzchnie ryzyka: nieograniczony koszt, utratę danych w logach i odpowiedzi, których kształtu nie można założyć. Guardrails zamieniają te oczekiwania w automatycznie egzekwowany standard kodu — dowodząc każdego naruszenia z realnych symboli SDK i zwykłej semantyki C#, bez żadnych dodatkowych atrybutów do wprowadzenia.

01

Przewidywalne koszty

Każde wywołanie modelu ma ustawiony dodatni limit MaxOutputTokens, więc koszt pojedynczego zapytania jest z góry ograniczony.

02

Bezpieczne dane

Surowe wiadomości i odpowiedzi nie trafiają do logów, a odpowiedź modelu jest deserializowana z opcjami odrzucającymi nieznane pola.

03

Stabilni agenci

ChatClientAgent ma deterministyczną nazwę, dzięki czemu jego stan (wątki, pamięć, telemetria) przeżywa restart procesu.

Katalog kontroli

Cztery reguły. Każda odpowiada na konkretną awarię.

Reguły działają wyłącznie na symbolach i przepływie danych Roslyn dowiedzionych z rzeczywistego SDK - żadna nie wymaga wprowadzenia własnego atrybutu znacznikowego. Dodatkowe API modeli, agentów i formatów odpowiedzi można wskazać w .editorconfig.

GP0141

Limit output tokens

Wywołanie modelu musi ustawić limit długości odpowiedzi i nie może przekazywać braku konfiguracji lub wartości niedodatniej.

Koszt
GP0143

Stabilna nazwa agenta

Agent otrzymuje deterministyczny identyfikator zamiast nazwy generowanej losowo lub zależnej od bieżącego czasu.

Obserwowalność
GP0145

Restrykcyjna deserializacja

Odpowiedź modelu jest deserializowana z jawnymi opcjami odrzucającymi nieznane pola, w typowany model zamiast dynamic.

Walidacja
GP0146

Brak surowych danych AI w logach

Wiadomości, odpowiedzi i kolekcje konwersacji rozpoznane po typie nie mogą trafiać bezpośrednio do loggera.

Prywatność
Egzekwowanie standardu

Od lokalnego IDE do quality gate.

Ten sam standard wspiera programistę podczas pisania kodu i chroni główną gałąź w pipeline.

1

Kod

Programista pisze integrację, korzystając wprost z typów SDK: ChatOptions, ChatResponse, ChatClientAgent.

2

4

Quality gate

Najważniejsze naruszenia mogą automatycznie zablokować wydanie.

Przykład w kodzie

Standard jest czytelny również bez dokumentacji obok.

Ryzykowna integracja
public async Task<Invoice> ExtractAsync(
    IChatClient client,
    ILogger logger)
{
    var response = await client.GetResponseAsync(prompt);

    logger.LogInformation("{Text}", response.Text);

    return JsonSerializer.Deserialize<Invoice>(
        response.Text)!;
}
Kontrolowana integracja AI
public async Task<Invoice> ExtractAsync(
    IChatClient client,
    ILogger logger)
{
    var options = new ChatOptions { MaxOutputTokens = 800 };

    var response = await client.GetResponseAsync(
        prompt, options);

    logger.LogInformation("model {Model}, {Tokens} tokens",
        response.ModelId, response.Usage?.TotalTokenCount);

    var jsonOptions = new JsonSerializerOptions
    {
        UnmappedMemberHandling = JsonUnmappedMemberHandling.Disallow
    };
    return JsonSerializer.Deserialize<Invoice>(
        response.Text, jsonOptions)!;
}
AI quality gate

Zamień zasady bezpiecznego AI w kod, który sprawdza się sam.

Guardrails nie oceniają jakości promptu ani decyzji biznesowych. Pilnują technicznych kontraktów, które da się jednoznacznie udowodnić podczas kompilacji — szybko, powtarzalnie i dla każdego zespołu.
